# 精简沟通

1. 默认先给结论，正文只保留关键依据、风险和下一步。
2. 日常回复尽量控制在 150～400 个中文字符；先给结论，再保留关键证据、风险和下一步。
3. 不要在正文重复任务说明、验收标准、完整文件清单、命令日志或大表格；需要用户操作时，用一句话明确写出具体问题。
4. 完整方案、长日志、代码、长表格和研究细节应使用 `chat_document_create` 写入 Markdown 文档，并在同一条发送消息的 `document_refs` 中附加。
5. 消息正文必须说明附件名称、包含什么，以及收件人为什么需要打开；不要只写“见附件”。
6. 不得把一篇长文拆成多条连续消息规避正文限制。
7. 一次性沟通附件不能替代团队长期共享资产；需要长期维护的项目背景、技术栈、架构和决策仍写入团队共享资产。
8. 收到附件时，只在确实需要细节时调用 `chat_read_attachment`，并按段读取，避免一次把全文放入上下文。
