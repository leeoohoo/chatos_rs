# 剧情模式（macOS）

## 公共 Agent Loop 实施进度（2026-09-09）

公共 `ChatOSAgentRuntime`、Memory Engine 用户鉴权接口适配与有界上下文协调已经实现；设置中新增「Agent 运行」，可配置默认 600 次调用与窗口/压缩预算。审批 Agent 已迁移公共循环，不自动云端同步审批文件。

剧情生产服务已切换到完整 function-calling loop，使用可见运行预算，并保存项目级运行检查点。剧情规划默认且固定使用 Memory Engine，同步文字记录、按预算请求压缩，不上传图片/视频二进制或密钥；开始规划时不再重复询问。审批仍不自动上传文件。

Agent 只规划文字；图片与视频由用户单项点击，或在确认页启动确定性制作队列。生产 `ChatOSStoryPlanningService` 通过 `AgentServiceProviding` 进入新循环；`StoryPlanningServicing` 仅作为内部测试接缝，不代表另一套剧情持久化格式。

详细方案保存在仓库根目录 `docs/plans/2026-09-09-reusable-agent-loop.md` 与 `2026-09-09-client-memory-engine.md`（根目录 docs 按仓库规则为本机文档）。

本批验证覆盖 API、Agent、审批、剧情、媒体、共享循环、关系图谱、确定性队列、提交防重、磁盘恢复，以及 Memory 摘要轮询正常完成和等待中取消两条防崩溃路径。验证不会触发真实付费请求。

## 页面与操作顺序

1. AI 创作 → 视频后面的「剧情模式」Tab → 剧情列表。
   剧情列表页标题栏提供独立「提示词中心」入口，不占用单个剧情内部的工作 Tab，也不依赖具体剧情。可按文本规划、Agent 工具、图片生成、视频生成筛选；表格展示稳定 Key、使用阶段、触发入口和代码位置，下方展示生产模板或工具协议。
2. 新建剧情填写标题、描述、文本模型、图片模型、视频模型。三类选择器展示账号现有可用模型，不要求 `task_enabled`。创建只落盘，不调用生成接口。
3. 工作台使用五个完整页面：剧情原文、画面风格、角色画像、拍摄分段、关系图谱。剧情与画面风格各自拥有大尺寸编辑区和 AI 优化；优化只返回候选，用户采用后再保存，不自动覆盖。
4. 点击「分析全剧并拆分计划」，确认文本调用预算；Memory Engine 默认用于记忆、压缩与恢复。Agent 分页读原文，保存全剧摘要、人物/场景文字画像和道具描述，再分批追加 2–15 秒剧情段与必要的 2–3 秒独立转场段（每批最多 5 个）。每段工具数据必须明确 `kind=story|transition` 与 `seconds`；剧情段连续覆盖原文，转场段位于两个剧情段的同一原文边界且不消耗原文。转场是 AI 在规划时针对明显时空或叙事跳变创建的正式分段，大多数剧情段直接衔接，界面不在每两个片段之间提供重复的“添加转场”提示。
5. 在「拍摄分段」细化所有未完成段，或只细化选中的一段；确认后仅提供冻结目标范围内的工具。逐段保存镜头提示词，可在当前步骤结束后暂停。工作台「草稿 / 运行记录」可查看中途画像、分段和实际动作，重启后可主动恢复；已有调用仍计入总预算。
6. 在「角色画像」生成、上传或从图片生成记录导入角色/场景/道具图片；生成后需要确认版本，历史图片版本保留。「关系图谱」显示分段引用及人物—场景关系，默认聚焦所选分段，可切换全剧。
7. 为每段分别生成首帧和尾帧，实际提交用户勾选的一张或多张已确认引用素材，不只把素材名称写进提示词。上一段确认尾帧会在本地直接成为下一段（包括转场段）的确认首帧，不调用图片模型；用户仍可主动重新生成、上传或选择替代首帧。转场尾帧再按同一规则成为后续剧情段首帧。
8. 可勾选一个或多个就绪分段并行生成视频；每段按项目 ID 与分段 ID 独立保存任务、进度和恢复 ID，一段失败或等待不会锁住其它分段与工作台。也可打开「批量制作 / 一键执行」，由程序按缺少的相关素材 → 首帧 → 尾帧 → 视频执行确定性依赖队列，不调用文本 AI；该依赖队列失败时才暂停后续步骤。MiniMax 原生 V2 可选择同时提交首尾帧；OpenAI 兼容 `/v1/videos` 只提交首帧。成功的视频可以单独播放。

## 提示词注册表

剧情模式的提示词统一登记在 `StoryPromptRegistry`。每项拥有稳定 Key（例如 `story.agent.system`、`story.image.first_frame`、`story.video.segment.transition`）、类别、用途、触发入口和实现位置。生产代码通过 Key 获取模板，并只在实际请求时注入当前项目、人物、场景和分段数据；提示词中心只展示全局注册模板，不读取或绑定任何具体剧情。

Agent 函数工具使用 `story.tool.<tool_name>` 作为界面审计 Key，内容直接读取 `StoryAgentTools.definitions` 当前的 Description 与 JSON Schema。提示词中心是只读审计界面，不调用模型、不生成媒体，也不产生费用。新增剧情提示词必须先加入注册表并补齐元数据，避免业务代码继续出现无法追踪的分散 Prompt。

## 规划工具与 MCP 边界

`StoryAgentTools` 按阶段提供实际参与循环的函数工具：

- 阅读：`story_read_state`、`story_read_graph`、`story_read_source`、`story_read_text`、`story_read_asset`、`story_read_asset_prompt`、`story_read_segment`。`story_read_graph` 分页返回项目、人物、场景、道具、分段节点以及引用/人物在场景中的关系；长原文、描述、风格、摘要和用户修改的图片提示词分页读取。
- 结构规划：`story_save_summary`、`story_append_segments`；验证唯一 ID、素材引用和原文连续覆盖。
- 人物文字画像：`story_save_character_profile`；包含主角标识、剧情身份、外貌、性格、动机、关系、服装和一致性。
- 场景文字画像：`story_save_scene_profile`；包含剧情作用、时代地点环境、空间布局、光线色调、关键陈设、氛围和一致性。
- 道具：`story_upsert_asset`；仅允许道具，人物和场景必须用独立画像工具。
- 镜头细化：`story_update_segment`；只写冻结目标，按该段 `seconds` 校验镜头从 0 连续覆盖到结尾。转场只连接前后画面状态，不推进新剧情。
- 关联写入：`story_save_segment_relations`；原子设置 `characterIDs`、`sceneIDs`、`propIDs` 和人物—场景关系，校验外键、动作位置及该段 `0...seconds` 区间。
- 阶段结束：`story_finish`；必须单独调用，由客户端确认完整性，不把调用预算耗尽当完成。

两类画像均为**文字，不是图片**，可在素材窗口和规划草稿中查看。保存画像只更新本地草稿，并派生可供之后手动生成图片的提示词，不调用媒体服务。原文未明确的外观/环境必须标注为视觉设定建议，不冒充剧情事实。多个分段复用相同素材 ID；已有媒体的素材不可被画像工具重写。

工具参数经过 Schema 与业务双重校验后保存。账号、项目 ID、文件路径、授权范围由客户端控制；剧情原文和模型返回均为创作数据，不是新的操作授权。图片与视频生成不暴露给规划模型，必须由用户操作确认。

这一版使用客户端内的函数工具调用，**没有新增对外的 MCP HTTP/stdio 服务**。业务模型与校验层可供后续 MCP 适配器复用，但不能把当前实现描述成已经部署了独立 MCP 服务。

## 模型与接口

- 沿用 `/ai-model-configs` 列表和现有按 ID 获取运行时配置的流程；不单独索取密钥，不将密钥落入剧情文件。
- 文本规划：当前支持 OpenAI 兼容 `chat/completions` 的函数工具调用。原生 Anthropic/Gemini 等协议未适配，会明确报不支持，不凭模型名称猜协议。
- 图片：复用生成/编辑接口；多图参考通过 multipart `image[]` 提交，最多 8 张。用户所选模型/中转需要支持多图编辑；拒绝时不会退化为忽略参考图的纯文生图。
- 视频：复用现有视频协议与模型能力表，提交每段自己的 `seconds`。若模型不支持某个 2–3 秒转场时长，客户端在提交前明确列出该段和模型支持时长，不创建假任务。OpenAI 兼容配置仍走 `/videos`，不会因 H3 名称而改成原生 MiniMax 路径。
- 剧情原文上限 80,000 字符，最多 200 段、100 个素材。输入含工具 Schema，按与 Task Runner 相同的完整 JSON `bytes / 4` 估算 token，不把原始字节直接当 token；客户端尚无供应商精确计数入口。瞬时文本请求错误会按可见设置重试，计入调用预算；无效工具参数回传给模型修正，不覆盖已保存内容。Memory Engine 压缩失败且输入超过硬窗口时会安全暂停。
- 文本规划使用 SSE 流式响应，工作台展示实时文字和工具组装状态。分片只存在于当前 UI，不写入业务草稿；完整结束并通过结构校验后才保存工具调用和执行结果。

## 本机存储与任务恢复

`Application Support/ChatOSSwift/StoryStudio/<账户 ID 的 SHA256>/<项目 UUID>/`

- 一个原子写入的 `project.json`，UUID 命名的本机媒体文件，以及 `runs/<运行 UUID>.json`。
- 规划运行文件保存完整审计消息、检查点、草稿、权限快照、工具回执及 Memory Engine 记录同步游标。摘要任务状态由 Memory Engine 管理；客户端恢复时查询 active-summary status，再直接使用 compose 返回的 blocks 与 recent records，不保存另一套摘要状态机。媒体制作使用独立批次文件，保存确定性步骤、写前意图和远端任务 ID；两类恢复记录不会混用。
- 阶段通过后，核对项目未被手动改动才应用；若已保存项目但未保存应用标记，可按最终内容摘要恢复。完成草稿再次应用不需要联网。不覆盖损坏的运行文件，显示无法读取数量。
- 新建、设置、规划、素材确认和任务状态逐步保存；切换账户清空内存，迟到的旧账号响应不会写进新账号界面。
- 损坏的项目文件保留，列表提示无法读取的数量，不覆盖损坏数据。
- 视频 POST 之前先保存提交意图，收到服务端任务 ID 后在继续轮询之前保存。
- 重新打开可点击「查询原任务 / 恢复下载」；这条路径只有 GET，没有重新 POST。
- 网络中断导致没有拿到任务 ID 时，禁止自动重发。用户可从服务商核实任务 ID 并绑定；或明确核对失败/未创建后允许手动重试。旧提交记录归档保留。
- 第一版不会在客户端关闭后继续调度，重新打开也不会自动恢复收费提交。
