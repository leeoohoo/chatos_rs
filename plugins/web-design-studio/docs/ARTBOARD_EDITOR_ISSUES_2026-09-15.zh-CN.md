# 画板编辑模型问题与修复记录（2026-09-15）

## 正确产品模型

工作区包含一个画板目录。每个目录项是独立的语义画板，可以是页面、菜单、弹窗、抽屉、浮层、Popover 或关键界面状态；它们不等同于桌面、平板、手机三个设备槽位。点击目录项时，中间只挂载和渲染该画板。宽度和首屏高度只是当前画板的尺寸属性。响应式规则属于单个画板内部，并且只在需求要求的宽度范围内建立。

顶部画板工具栏始终且只作用于正在编辑的当前画板。画板保留明确的布局宽度，供布局、截图和命中测试使用；高度不再是用户维护的尺寸，而是由当前画板全部可见内容的最底边自动计算。Scene 根节点、历史 viewport 高度和画板类型都不能反向锁住画板高度。创建新画板和工作区缩放属于全局工作区动作，应放在工作区工具栏。

## 问题清单

### 1. 顶部工具栏作用域混乱

- 现象：当前画板尺寸、设备入口、创建画板、显示全部、流程线和全局缩放混在同一条工具栏中。
- 根因：UI 没有把 `activeArtboardId` 作为整条顶部工具栏的唯一作用域。
- 修复：左侧提供可点击的画板目录；顶部只显示当前画板名称与尺寸，并保留尺寸、旋转、布局规则、适应选择、聚焦、复制和当前画板交互。
- 验收：切换画板后，顶部名称和尺寸立即切换；顶部操作不会修改其他画板。

### 2. 画板被错误绑定为桌面、平板、手机

- 现象：工具栏把三种设备作为画板的一级分类，容易引导用户和 AI 为设备重复建设页面。
- 根因：旧编辑器的 breakpoint 模型被直接暴露为多画板模型。
- 修复：删除设备三分入口；提供中性的画板尺寸预设和自定义尺寸；响应式只作为当前画板内部的可选布局规则。
- 验收：工具栏不出现桌面、平板、手机分类；AI 默认按页面、菜单、弹层和状态规划画板，不按设备复制画板。

### 3. 改宽画板覆盖其他画板

- 现象：画板从 1440 调整到 2560 后，右侧画板仍停在旧坐标并被覆盖。
- 根因：把目录中的所有画板错误地当成同一世界坐标内的平铺对象。
- 修复：删除世界坐标布局语义；目录项的遗留 `x/y` 固定归零，任何时刻只渲染当前画板。
- 验收：1440 → 2560 只改变当前画板；其他画板不挂载、不移动，也不可能被覆盖。

### 4. 固定 Scene 根节点与画板尺寸不一致

- 现象：当前画板看似改宽，刷新后又被固定宽度 Scene 根节点恢复，或画板边界和内容根节点不一致。
- 根因：工作区 placement 被修改，但对应页面的固定 Scene 根节点没有同步。
- 修复：调整页面画板宽度时同步该页面根节点的 `frame.width`；失败时回滚 placement。
- 验收：刷新、重启插件后尺寸不回退，其他画板 Scene 不变。

### 5. 应用级“全屏预览”与多画板编辑模型冲突

- 现象：顶栏的“全屏预览”脱离当前画板编辑语境，进入另一套全局页面路由和缩放状态；宽画板会被错误放大、截断，也让用户无法判断操作目标。
- 根因：旧的整站页面预览模式与新的语义多画板工作区并存，使用两套 Camera、路由和叠层渲染规则。
- 修复：删除应用级“全屏预览”入口及整套独立预览模式；预览交互统一放回“交互当前画板”，页面跳转激活目标画板，弹窗、抽屉、菜单和浮层在当前画板交互模式中展示。
- 验收：顶栏不再出现“全屏预览”；编辑器始终保留当前工作区上下文；“交互当前画板”仍可验证页面跳转和叠层关系。

### 6. Skill 画板规划引导错误

- 现象：AI 容易默认创建桌面、平板、手机三套画板，而忽略菜单、弹层和关键状态。
- 根因：路由和响应式 Skill 使用设备分类描述主要工作流。
- 修复：Skill 明确“语义画板优先、响应式宽度规则其次”，禁止在用户未要求独立设备方案时按设备复制画板。
- 验收：新任务的 Site Plan 先覆盖导航目的地和重要交互状态；只为 brief 要求的宽度做同画板响应式验证。

### 7. 页面越多，操作越卡

- 现象：画板数量增加后，编辑、缩放和改宽明显卡顿。
- 根因：非当前画板仍挂载 DOM、组件库 runtime，并参与画布位置与跨画板流程线计算。
- 修复：只挂载当前目录项；删除跨画板 SVG 流程线与画板拖动；选择聚焦只计算当前画板。
- 验收：增加目录项不会线性增加当前画布 DOM/runtime 数量；切换后旧画板立即卸载。

### 8. AI 一次读取全部画板，注意力与 token 被稀释

- 现象：模型读取整站 Scene 后才自行筛选，回包大且容易误改其他画板。
- 根因：工具协议把画板集合当成一个查询面。
- 修复：`get_active_context` 返回紧凑画板目录；AI 为 `query_scene`/`edit_scene` 明确选择一个 `artboardId`，服务端拒绝跨画板编辑。
- 验收：一次查询只返回一个画板节点；一次编辑的全部节点必须属于同一 `artboardId`。

### 9. 收起左侧栏后找不到画板目录

- 现象：左侧“页面与图层”面板收起时，画板目录也一起消失，只剩一列难以识别的图标。
- 根因：把核心工作入口错误地放进了可选属性面板。
- 修复：在画布顶部提供始终可见的横向“画板目录”条，直接显示序号、名称、语义类型和当前状态；左侧完整目录仍用于批量管理，不再用一个小下拉框冒充目录。
- 验收：无论左右面板是否展开，用户都能看到当前画板并一键切换其他画板。

### 10. 画板高度被预设、历史 viewport 和 Scene 根节点锁死

- 现象：工具栏显示 `1440 × 自动 900`，但把 Button 等组件拖到原内容区域下方后，画板仍不增长；旧根节点只有 768 高时还会在底部出现白色空区。
- 根因：`sceneArtboardContentHeight` 只读取根节点求解高度，并用保存的 viewport 高度做永久下限；绝对定位节点、刚拖入的组件和越过根节点的内容都没有参与画板边界计算。
- 修复：顶部只编辑布局宽度，高度改为只读自动值；尺寸模板只做一次性宽度/初始参考赋值；画板高度扫描当前页面全部可见求解节点，使用 `y + max(height, contentHeight)` 的最大底边，旧 viewport 高度只在 Scene 无法求解时兜底。渲染时页面根背景同步延伸到这个真实内容边界。
- 验收：旧根节点 768、高度记录 900、Button 放到 `y=1040` 时画板实际高度为 1080；Button 移回内容区后画板收缩回 768；其他画板的节点不参与当前画板计算。

### 11. 3.0.17 把小下拉框误当成目录

- 现象：顶部出现“画板目录”文字和一个很小的原生下拉框，但用户无法一眼看到项目有哪些画板，也无法确认当前画板在整个设计中的位置。
- 根因：实现只满足了“有一个可切换控件”，没有满足“目录始终可见、全部条目可扫描、当前项明确”的产品目标。
- 修复：删除顶部目录下拉框，在画布工具栏下增加独立横向目录条；目录项直接显示编号、名称和页面/弹窗/抽屉/菜单等语义类型，当前项有明确选中态，条目过多时仅目录自身横向滚动。
- 验收：当前 WMS 真实 Scene 的 9 个画板均出现在目录条；左右面板开关不影响目录；点击条目仍只挂载目标画板。

### 12. 拖动结束后画板才改变高度

- 现象：把元素向画板底部拖动时，内部内容已经越过边界，但外层画板要等松手提交后才突然增高。
- 根因：`SceneArtboardCanvas` 使用实时 `previewScene` 计算内容高度，外层 `WebDesignStudioApp` 却只使用已提交的 `sceneDocument`；两层高度源在手势期间不一致。
- 修复：内层在动画帧中把预览高度回传给当前画板外层；松手提交后再切回持久 Scene 的高度，避免每个原始 pointer event 都触发父层更新。
- 验收：元素底边越过当前画板时，画板与根背景在拖动过程中立即增长；取消或提交手势后高度与最终 Scene 一致。

### 13. 低缩放比例下移动和八向缩放发生漂移

- 现象：在 30% 等缩放比例下移动或缩放元素会抖动、滞后，经过 Ant Design 等 iframe runtime 时还可能丢失一段位移，松手后的结果与最后预览不一致。
- 根因：旧交互把手势状态存在 React state 中，每次 pointer move 都重绑全局监听器；没有 Pointer Capture，指针进入 iframe 后父页面无法持续收到事件；pointer up 还可能读取到上一帧的 delta。
- 修复：手势开始时捕获指针；用 ref 保存一份不可变起始 Scene、起点和缩放比例，并在同一个稳定监听器中更新最终 delta；手势期间临时关闭 iframe 命中，松手使用最后一次真实 delta 提交。
- 验收：30%、100% 和放大视图下，移动与八个缩放手柄都持续跟手；经过 iframe 不丢事件；南/东缩放保持左上角不动，北/西缩放保持对边不动；松手后不跳回上一帧。

### 14. 快速连续拖动时元素放下后又回去

- 现象：一次拖动刚松手便继续拖动，第二次预览会从旧位置开始，放下后元素有时又回到上一次或更早的位置。
- 根因：Scene 保存是异步操作，但旧交互在 `pointerup` 后立即结束 transforming 状态。上一笔尚未完成时，下一笔会从旧 `scene` prop 和旧 revision 建立快照；两笔命令还可能携带相同 expected revision，冲突刷新后就表现为元素回退。
- 修复：所有 Scene 编辑命令通过单一队列串行执行，每笔真正执行前读取最新 Scene revision；非零拖拽在保存完成前保留 `previewScene` 和 transforming 锁，禁止开启下一次移动或缩放，成功或失败后再统一释放；`pointercancel` 只取消预览，不错误提交。
- 验收：快速连续拖动不会从旧位置起步、不会在放下后回退，也不会因连续手势产生 revision conflict；保存期间画面保持最后预览位置。

### 15. 修复回退后必须等待保存才能继续拖动

- 现象：3.0.20 虽然不再回退，但松手后要等待服务端保存和历史记录刷新完成，元素才允许再次拖动；网络或磁盘稍慢时会明显卡手。
- 根因：把“保证后台提交顺序”和“阻塞前台手势”错误地绑定成同一个锁，并把非关键的历史记录读取放在 Scene 命令的关键完成路径上。
- 修复：松手时立即把最终预览提升为本地 optimistic Scene，结束当前手势并允许下一次拖动；下一手势从 optimistic Scene 而不是旧 prop 建立快照。后台命令仍严格串行并在执行时读取最新 revision；历史记录改为非阻塞刷新，使用请求序号丢弃过期回包。最后一笔确认后再无闪烁地收敛到服务端 Scene，失败时才撤销 optimistic 状态。
- 验收：连续快速拖动无需等待保存；每次都从刚刚放下的位置继续；后台 revision 单调递增，最终服务端位置与最后一次预览一致；历史接口变慢不会锁住拖拽。

### 16. 项目首页的设计删除按钮无响应

- 现象：点击设计卡片右侧的 `×` 后没有任何界面反馈，设计也没有删除。
- 根因：删除流程依赖浏览器原生 `window.confirm`；插件运行在受限制的嵌入式页面时，宿主可能禁止原生 JavaScript 对话框，确认调用会直接失败或返回取消，导致删除接口从未执行。
- 修复：改用插件自身的 `alertdialog` 确认弹窗，不再依赖宿主原生对话框；确认后显示“正在删除”，禁用重复提交，完成后重新读取项目和设计目录。服务端回归测试同时验证文档文件被删除、项目 `designIds` 移除对应条目。
- 验收：项目首页和编辑器内的设计目录都能打开同一删除确认弹窗；取消不改变数据；确认后卡片消失、刷新不恢复，连续点击不会重复请求。
