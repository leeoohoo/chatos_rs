# Scenarios and verification

Choose evidence according to the actual remote capability, not the user's profession alone.

## Development and operations

For repository, issue, deployment, or monitoring tools, bind calls to the requested repository/environment/ref and distinguish inspection from mutation. A returned job ID means submission, not deployment success. Use an exposed status/read tool to establish the final state, capture the relevant revision or job identity, and connect it to Task acceptance criteria. If the Task also edits local code, keep remote changes and local verification distinct; remote tool access does not extend `owned_paths` or authorize production changes.

## Design and creative production

For asset catalogs, remote design files, or image services, specify the chosen asset/file, format, dimensions, and intended output. Avoid changing a shared design file just because a preview needs adjustment. Verify output existence and accessibility using exposed metadata/preview/status tools; distinguish a generated preview from an editable source or published deliverable. Record limitations when the remote server cannot expose a visual preview or export confirmation.

## Writing, documents, and marketing

For CMS, knowledge base, or document tools, retain the user's audience, factual constraints, language, and delivery format. Drafting and publishing are different authorities. Do not publish, email, or replace an existing remote document unless the request includes that action. Verify the returned document/version and content or export status; an upload receipt alone does not prove formatting or publication. Cite source identities for researched claims and distinguish sourced facts from suggestions.

## Research and data analysis

Bind searches and queries to the requested sources, date range, filters, and pagination. Establish completeness or explicitly disclose partial results. Preserve query/source identifiers, units, and transformation assumptions. A successful tool response does not validate a statistical conclusion; check sample coverage and arithmetic before summarizing. If the server provides only a small page, do not claim a full-dataset analysis.

## Missing capabilities

Use only the current catalog. If it lacks a verification, export, status, or required business operation, report what is actually available and which acceptance item remains unverified. Do not silently replace a requested editable artifact with prose or count an inaccessible remote link as a delivered file.
