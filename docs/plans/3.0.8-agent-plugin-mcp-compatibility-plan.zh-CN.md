# ChatOS Agent Plugin / Skill / MCP 兼容安装方案

## 1. 目标与边界

ChatOS 的插件安装能力按“来源获取、格式归一化、隔离预检、指纹确认、运行时执行”五层实现。用户可以在独立的“插件安装助手”聊天中用自然语言安装，也可以在设置页手动操作。项目聊天、项目 Task 和普通联系人不得获得任何安装工具。

本轮 macOS 实现覆盖 Codex、Claude Code、Cursor、VS Code、Gemini、Cline/OpenCode 等主流 Agent 应用中可移植的本地 Plugin、Skill 与 stdio MCP 包。Windows 本轮不开发，但后续实现必须复用本方案的数据契约、安全约束和验收夹具，不得另建一套宽松格式或旧数据兼容层。

## 2. 统一安装流水线

```text
自然语言安装助手 / 手动 UI
              |
              v
  Source Adapter（本地 / Git / npm）
              |
              v
 Format Adapter（Plugin / Skill / MCP）
              |
              v
 隔离复制 + 路径校验 + 禁止安装脚本
              |
              v
 启动 MCP 并读取真实 tools/list / 校验 Skill
              |
              v
 SHA-256 指纹确认后重新获取并复检
              |
              v
      原子写入本机 Plugin 安装记录
```

安装助手不拥有终端、项目、任务或文件编辑工具。安装必须先预检，再用完全相同的来源参数和预检指纹提交；来源在确认后发生变化时拒绝安装。

## 3. 来源兼容矩阵

| 来源 | macOS | 要求 |
|---|---:|---|
| 本地目录 | 已实现 | 绝对路径；来源不能包含 ChatOS 安装目录；复制后解析 |
| HTTPS Git | 已实现 | URL 不得含凭据、query 或 fragment；支持 branch/tag/commit 和 monorepo 子目录；禁用 hooks 与 file protocol |
| npm MCP 命令包 | 已实现 | npm 精确版本、声明的 bin、结构化参数；`--ignore-scripts` |
| npm 完整 Agent Plugin | 已实现 | npm 精确版本；复制完整包与依赖；`--ignore-scripts` |
| 市场按名称发现 | npm 已实现 | 搜索结果与 README 只视为不可信元数据 |
| Git/市场聚合索引发现 | 后续 | 只增加发现适配器，不改变安装与指纹协议 |

## 4. 格式兼容矩阵

| 格式 | macOS | 入口 |
|---|---:|---|
| ChatOS Plugin schema v3 | 已实现 | `chatos.plugin.json` |
| Portable Agent Plugin | 已实现 | `plugin.json` |
| Codex Plugin | 已实现 | `.codex-plugin/plugin.json` |
| Claude Plugin | 已实现 | `.claude-plugin/plugin.json` |
| 独立 Agent Skill | 已实现 | 根目录 `SKILL.md` 或 `skills/*/SKILL.md` |
| 通用 MCP JSON | 已实现 | `mcp.json`、`.mcp.json` |
| Cursor / VS Code | 已实现 | `.cursor/mcp.json`、`.vscode/mcp.json` |
| Gemini / Claude Desktop | 已实现 | `.gemini/settings.json`、`claude_desktop_config.json` |
| Cline / OpenCode | 已实现 | `cline_mcp_settings.json`、`opencode.json` |
| stdio MCP | 已实现 | PATH 命令或包内可执行文件；参数不经过 shell 解析 |
| Streamable HTTP / SSE MCP | 独立后续阶段 | 必须接入现有 External MCP HTTP Runtime 与系统凭据存储，不能用 shell/curl 桥接冒充完成 |
| 外部 Plugin UI/App | 独立后续阶段 | 必须有明确的 UI runtime 与权限模型，不能只复制文件就宣称可用 |

“清单可以解析”不等于“所有贡献类型都能执行”。当前安装器只接受能被真实验证并运行的 Skill 或 stdio MCP；远程 HTTP/SSE 和外部 UI/App 在对应运行时完成前必须明确拒绝。

## 5. 安全约束

- npm 永远固定精确版本并使用 `--ignore-scripts`，不执行依赖生命周期脚本。
- Git 获取禁用 hooks、交互式凭据和 `file://` protocol；安装来源不得把令牌嵌入 URL。
- 目录、子目录、Skill 和可执行入口都必须位于隔离包根内，符号链接在预检前移除或拒绝。
- MCP 命令与参数分项保存，不拼接为用户可注入的 shell 命令。
- 环境变量不得从安装聊天收集明文 Secret；后续远程 MCP 凭据只进入 Keychain/Windows Credential Manager。
- 预检读取真实 `tools/list` 并纳入指纹；安装时重新获取来源并复检，失败关闭。
- 安装能力只发布给系统联系人 `plugin-installer`，普通 Main Chat、项目聊天和 Task Executor 均不得看到这些工具。

## 6. Windows 后续要求

Windows 实现由单独开发任务完成，至少包括：

1. 复用相同的 Source Draft、归一化 manifest、组件清单与指纹算法测试向量。
2. Git 获取使用无交互凭据模式并禁用 hooks/file protocol；npm 同样固定版本且禁止 scripts。
3. 路径校验使用 Windows canonical path、reparse point 与 per-user 安装目录 ACL，不照搬 POSIX 字符串前缀判断。
4. stdio MCP 使用受管进程树/Job Object，取消、超时与卸载必须终止全部子进程。
5. Secret 进入 Windows Credential Manager/DPAPI，不进入 JSON、SQLite、日志或模型上下文。
6. 安装工具仍只发布给独立安装助手；项目聊天没有工具这一约束必须有跨端契约测试。
7. 完成后在 Windows 11 真机运行编译、安装、重启恢复、REA MCP、纯 Skill、Codex Plugin、Git 与 npm 来源的端到端验收。

## 7. macOS 验收门禁

- 完整 Swift 测试通过。
- Rust `plugin_installer_main_chat_exposes_only_installer_tools` 通过。
- REA 固定版本真实端到端预检、安装、持久化和 Main Chat 组件发现通过。
- Codex、Portable Agent Plugin、独立 Skill、VS Code MCP JSON 与指纹漂移测试通过。
- 本地化审计与 `git diff --check` 通过。
- Release 必须从已提交的干净 worktree 构建，安装后的 `Info.plist` Git commit 与提交一致。
