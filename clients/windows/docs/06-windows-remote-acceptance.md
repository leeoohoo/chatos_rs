# Windows 远端 SSH、SFTP 与终端验收

## 测试环境

准备以下 SSH 主机：

- 一台可直接连接的 Linux 主机。
- 一台只能通过跳板机访问的目标主机。
- 密码、Ed25519/RSA 私钥、OpenSSH 用户证书三种账号。
- 至少一个启用 TOTP 或 keyboard-interactive 的账号。

Windows 构建后先运行全部测试：

```powershell
dotnet build ChatOS.Windows.sln -c Debug -p:Platform=x64
dotnet test ChatOS.Windows.sln -c Debug -p:Platform=x64 --no-build
```

## 连接与本机凭据

1. 从侧栏进入远端连接，新建密码连接并选择已配对的本机 Connector 工作区。
2. 保存后确认密码框清空；重新打开编辑器时不得回显密码、私钥内容或其他 Secret。
3. 检查服务端远端连接记录，确认不含密码、私钥路径、证书路径和跳板机凭据。
4. 分别测试密码、私钥和私钥加证书认证；删除连接后 Credential Manager 中对应凭据必须删除。
5. 模拟 Credential Manager 保存失败，云端不得残留只有元数据、没有本机凭据的半成品连接。

## 主机密钥与二次验证

1. 新主机使用“严格校验”应拒绝未知指纹并给出可操作提示。
2. 核实服务器指纹后切换“首次接受”，连接成功并保存 SHA-256 指纹。
3. 服务器主机密钥变化后必须拒绝连接，不能静默覆盖旧指纹。
4. 对启用 TOTP 的账号测试连接，客户端应原地展示服务端 prompt；输入验证码后重试成功。
5. 在跳板机和目标机分别启用二次验证，确认提示来自实际失败的连接阶段。

## 跳板机

1. 选择已有连接作为跳板机，确认自动解析其主机、端口、用户名和本机凭据。
2. 测试直接填写跳板机参数以及密码/私钥两种认证。
3. 断开跳板机网络，目标连接必须失败，不得退化成目标直连并报告成功。
4. 抓取网络连接，确认目标 SSH 通过 `127.0.0.1` 临时端口转发，退出后端口和两个 SSH 会话均释放。

## SFTP

1. 浏览默认目录和多级子目录，进入目录和返回上级路径正确。
2. 预览 UTF-8 文本；超过 2 MB 或二进制文件应提示下载，不得把乱码塞进编辑区。
3. 上传文件；同名文件默认拒绝，确认后才覆盖。
4. 下载中文名、空格名和二进制文件，校验字节完全一致。
5. 新建目录、重命名文件和目录、删除文件、递归删除目录。
6. 删除符号链接时只删除链接，不得递归进入链接目标；超过 10,000 个递归条目时停止并提示。
7. 在上传、下载和目录加载期间取消或断网，页面恢复可操作且 SSH/SFTP 会话释放。

## 远程终端

1. 输入 `pwd`，确认初始目录使用连接的默认远端目录。
2. 执行 `cd /tmp && pwd` 后再执行命令，下一次提示目录应保持为 `/tmp`。
3. 分别验证 stdout、stderr 和非零退出码显示。
4. 执行长时间命令并点击取消，连接及时释放且可再次执行。
5. 运行产生超大输出的命令，客户端不得卡死；单次 stdout/stderr 显示分别限制为 200,000 字符。
6. 验证包含单引号、中文、换行和 shell 管道的命令，工作目录和退出码解析不能被破坏。
7. 通过跳板机与二次验证重复上述终端测试。

## 通过标准

- Secret 只存在于 Windows Credential Manager，不进入 API 请求、SQLite、日志或错误正文。
- 跳板机和目标主机均独立完成主机密钥与认证校验。
- 所有取消、超时、断网和页面退出路径都释放 SSH、SFTP、端口转发及远端临时文件。
- 侧栏、编辑器、SFTP 和远程终端在同一连接身份下状态一致。
