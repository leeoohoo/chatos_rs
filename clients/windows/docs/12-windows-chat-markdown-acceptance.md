## 代码块与原生选择

1. 显示包含三行以上代码的回复，核对代码内部行距连续，段后间距只用于代码块与后续正文之间；缩进、Tab、空行、尾部空格和中文保持。代码中的 `**literal**`、`_identifier_`、反引号及链接样式文本必须按字面显示。
2. 只选择代码正文，用 Ctrl+C 和原生右键菜单复制到本地纯文本编辑器，开启空白字符显示，比对行数、缩进、空行与尾部空格。允许平台剪贴板将 LF 转成 CRLF；不得额外插入空行、遗漏原有行或混入围栏标记。不要读取已有剪贴板历史或其他用户内容。
3. 连续放置两个没有正文间隔的围栏块，核对它们保持独立；空代码块、仅一个空行的代码块及前后正文也应显示稳定。短围栏、不同围栏字符、关闭围栏后带正文的标记不能提前关闭代码块。
4. 核对 LF、CRLF、CR 三种输入，以及模型流式回复尚未闭合的代码块；尾部新行继续保留在当前块中，闭合后后续正文恢复普通样式。记录流式更新时的选择、滚动及复制行为，不能仅凭解析器测试判定原生交互通过。
5. 普通标题、列表、引用、行内样式、安全链接和消息附件仍按各自样式显示；用户消息的原生选字不受影响。跨正文/代码块选择后复制，比对边界是否符合 Windows 原生文本规则。
6. 在记事本预览、项目 Markdown 预览、任务过程/报告、Agent 文档和 Pet 文件预览中复测共享渲染器；在中英文、不同字体缩放和窄窗口核对长行、焦点、读屏及多行选择。分别记录各入口的通过、失败、受阻和未执行。

## 普通段落软换行（2026-10-14 16:05）

Mac 行为以 `MarkdownBlockParser.swift.flushParagraph` 为依据：去掉每行边界空白，将同段普通源行用一个空格连接，再交给原生行内 Markdown。Windows 的共享阅读器现在采用同样的普通正文段落规则，围栏代码正文继续保留原始空白和 LineBreak。

## 六级标题与正文分类（2026-10-14 16:20）

19. 在真实聊天和共享预览入口显示一至六级标题。四至六级不再显示开头的井号，采用 Windows 原生正文大小和强调字重；前三层保持现有 24/19/16 的字体层级。标记后必须有空白和非空正文，Tab 或 Unicode 空格可分隔，正文中的额外空格/Tab 保留，标记周围空白去掉。

    ````markdown
    # Heading 1
    ## Heading 2
    ### Heading 3
    #### Heading 4 **bold**
    ##### Heading 5 `code`
    ###### Heading 6 [link](https://example.test)
    ````

20. 单独检查 `#`、空正文的标题标记、七个以上井号、没有分隔空白的 `####text`、转义的 `\#### text`。这些都是普通正文；即使它们后面紧接另一普通源行，合并后也不得被重新解释为标题。类似地，只有 `-` / `+` / `*` / `12.` 的源行与后文合并后不得突然变成列表。Mac 当前解析器保留标题末尾的 `##`，Windows 同样保留，不将此视为完整 CommonMark 关闭标记支持。
21. 检查标题内部的粗体、行内代码和原生链接，代码围栏内的井号必须保留字面。复测深浅主题、窄窗口、选择/复制、焦点和读屏。独立样本已核对原生段落字重、链接 URI、正文分类和三张截图；真实聊天/共享入口的手动复制、链接激活和辅助技术仍未验收。
