# Apple 风格 UI 规范

## 设计原则

1. **工作面优先**：中心区域永远服务当前任务，状态卡不占据不必要的空间。
2. **层级来自空间与材质**：Sidebar、Workspace、Inspector 用系统 material 区分，不靠粗重边框。
3. **渐进披露**：默认显示结论和下一步，日志、参数、原始事件进入 DisclosureGroup 或 Inspector。
4. **系统行为一致**：菜单、快捷键、Toolbar、Settings、Window、Search 遵循 macOS 习惯。
5. **状态可恢复**：离线、权限不足、任务阻塞和插件崩溃必须给出明确原因和单一主要动作。
6. **密度可控**：默认舒适密度，代码、终端、任务时间线允许紧凑模式。
7. **拒绝卡片套卡片**：设置与管理页不使用“灰色大画布 + 居中白色巨型卡片 + 卡片内再套卡片”。优先采用独立 Settings 窗口、原生分栏、连续 Form 和系统分隔线。
8. **留白必须有用途**：短表单保持紧凑，长列表占满可用宽度，不能为了居中制造大面积无意义空白。

## 视觉 Token

| Token | 建议 |
| --- | --- |
| App 背景 | `Color(nsColor: .windowBackgroundColor)` |
| Sidebar | `.sidebar` / system material |
| Inspector | `.ultraThinMaterial`，仅在有层级意义时使用 |
| 主强调色 | System Blue；不要自造高饱和品牌蓝 |
| 成功 | System Green |
| 警告 | System Orange |
| 危险 | System Red |
| AI 活动 | 低饱和 lavender，仅作小面积状态色 |
| 圆角 | 8 / 12 / 16，不使用夸张胶囊卡片 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 |
| 阴影 | 只用于浮层、Popover、Window 内悬浮 Composer |

## 字体

- 页面标题：`.title2.weight(.semibold)`。
- 分组标题：`.headline`。
- 正文：`.body`。
- 次级信息：`.subheadline` / `.caption` + secondary color。
- 代码、路径、命令：SF Mono。
- 禁止把大段全大写英文当作装饰 eyebrow。

## 窗口与导航

- 主窗口最小尺寸建议 1100×720，默认 1440×900。
- 左侧资源栏 220–280 pt，按“联系人 / 项目 / 终端 / 远端”分区；它是现有产品的一级导航，不新增 Command Center。
- Toolbar 保留当前资源标题、记事本、主题、账号以及上下文相关动作；新版不实现原项目的应用快捷方式入口。
- 选中项目后，在内容区顶部显示“项目目录 / 用户消息 / Plan / 项目设置”四个 Tab。
- Inspector 只在任务图节点、Run、Git 比较或其他明确的主从详情关系中出现，不作为所有页面的固定第三栏。
- 创建项目、终端、远端连接使用 Sheet；任务执行工作台、系统上下文可使用独立窗口或全屏工作面。
- 用户偏好使用独立 `Settings` Scene：左侧分类，右侧连续表单；不携带联系人/项目资源侧栏。
- 记事本使用独立文档窗口：导航侧栏 + 直接编辑的文档面；标题和正文不是套在表单卡片中的输入框。
- Plugin 实时画面固定在主窗口内容区右下角，独立于聊天滚动和当前项目 Tab；只在当前会话与 visual session owner 匹配时显示，审批浮层始终在它上方。

## 关键组件

### Conversation

- 项目会话与联系人会话都使用单一全宽时间线，不再额外复制一列“用户消息”Turn 列表。
- 用户消息与 Assistant 回复按时间线连续展示；只有真实包含任务运行的 Turn 才显示任务卡片和“查看任务”入口。
- 点击任务入口后展示该 Turn 对应的真实任务/工具/推理节点；普通用户消息不生成任务入口。
- 任务消息卡保留“查看过程 / 查看详情 / 任务图”：前两项是消息回调级入口，任务图是一条用户消息经 AI 调用 Task Runner MCP 后创建的一个或多个任务节点。
- 任务图中的每个节点都独立提供执行过程、任务详情、运行详情与阻塞处理，不能把整张图降级成单一过程列表。
- Task Runner 已取消并删除的任务回调不作为聊天回复或过程节点展示；保留失败、阻塞、完成等仍有诊断价值的真实记录。
- 工具调用默认摘要为“动作 + 目标 + 状态 + 耗时”，原始参数折叠。
- Composer 显示模型、附件、Task Plugin 偏好、规划模式和推理开关；执行中允许发送 runtime guidance。
- 规划开关只在存在明确项目上下文时可用；状态持久化到会话 runtime settings，并作为 `/agent/chat/send` 的 `plan_mode` 发送。开启时先生成待确认任务图，不能直接等同于“立即执行”。
- 项目任务图顶部按真实状态显示“生成中 / 等待确认 / 执行中 / 完成 / 阻塞 / 失败 / 已停止”。等待确认时提供“确认执行”和“放弃计划”；放弃属于破坏性操作，必须经过系统确认框。
- 只有消息元数据明确给出 `project_id`、`requirement_id`、`execution_group_id`，且存在 `conversation_id` 时才能启用执行动作；客户端不得用 message ID 或 turn ID 猜测执行批次。
- 任务运行时在 Toolbar 与 Composer 同时提供停止/补充引导入口。

### Task DAG

- 保留当前产品的重要语义：依赖方向、直接/间接前置、运行态连线、聚焦弱化、缩放和 Inspector。
- 节点颜色只表示状态，不表示任务类型。
- 键盘可选择节点；VoiceOver 读出任务名、状态、依赖数量和可用动作。

### Project Workspace

- 两区：文件树与搜索 / 文件预览或编辑；树宽可调整。
- Git 操作放在项目 Tab 右侧的 Toolbar menu 和专用弹层，不保留固定 Changes Inspector。
- 文件预览与编辑共享 tab model；未保存状态遵循 macOS 文档窗口习惯。

### Project Plan

- 首页是 Requirement 多列导航与选中 Requirement 详情，不是 DAG 画布。
- 详情包含“需求 / 技术文档 / 任务”三个 Tab，以及预览流程和执行工作台入口。
- DAG 只用于流程预览、Requirement 执行工作台和消息任务详情。
- Requirement 执行工作台采用“规划过程 Sidebar + 实时任务依赖图 + 底部执行动作”的真实结构；任务列表不能替代 DAG 主工作面。
- 等待确认时可以反馈并重新规划，右侧流程图随任务创建实时更新；确认后才按依赖顺序执行，暂停/停止只在真实运行阶段出现。

### Local Connector

- 设置窗口按真实功能分为：设备配对、外挂程式、本机终端、模型配置、命令审批、运行与权限、权限控制。
- “连接正常”不是绿色大横幅，只在标题旁显示小状态标记。
- 权限页区分 macOS 系统权限、插件进程权限、任务文件/网络策略和命令审批策略。
- 待审批用菜单栏 badge 和原生通知，不用持续闪烁。
- 云端模型只读同步；本机仅配置命令审批模型、重试次数和 Thinking。

### Plugin Visual Session

- Expanded 默认 376×276 pt；Collapsed 为 168×44 pt，位于内容区右下角并保留 18 pt 边距。
- 标题显示 Plugin 名称；副标题显示实时点和目标应用；帧区只展示本机实时画面；底部显示 Plugin 标识和“仅在本机显示”。
- 新 `sessionID` 自动展开；无有效会话时完全隐藏；等待首帧时显示轻量进度，不显示旧帧冒充实时状态。
- 浮层不进入消息列表，不改变聊天历史高度、滚动锚点或“是否在底部”的判断。
- 不设计 Computer Use 页面或 Browser MCP 页面；两者只是当前会话执行中的实时帧来源。

### Chat History

- 聊天历史是正常会话的一部分，不设计独立的“恢复测试”或诊断页面。
- 底部始终是正常 Composer：模型、附件、Plugin 偏好、规划、推理、消息输入和发送按钮；任务执行中仍可发送引导。
- 用户界面只显示可理解、可操作的状态：加载更早消息、加载失败与重试、离线/重连、发送失败，以及离开底部后的“新消息”按钮。
- `TurnID`、cursor、revision、generation、event sequence、缓存数量、加载范围和锚点偏移属于内部实现与测试诊断，禁止出现在产品界面。
- Realtime/HTTP/SQLite 的合并来源和连续性属于数据层健康信息；除非连接异常需要用户处理，否则不显示技术状态标签。

### Terminal

- 终端画布必须跟随应用浅色/深色主题，浅色模式使用系统窗口背景和高对比度 ANSI 色，禁止整页强制深色。
- 主工作面优先给 PTY viewport；连接、shell、字符编码和行列数进入底部细状态栏，不使用占据大量高度的“会话状态”卡片。
- 多终端使用可关闭的原生 Tab；左侧资源栏仍是所有终端的权威列表，Tab 只表示当前窗口已打开的会话。
- 顶部 Toolbar 只保留搜索、创建终端和更多菜单；重连、清屏、重命名、关闭/删除等低频或危险动作进入菜单。
- 不提供独立命令历史侧栏；命令回溯使用 shell 自身的上下键、`history` 与反向搜索，终端 viewport 默认占满工作面。
- 只有命令正在执行时才显示“中断”；断线或历史加载失败使用紧凑 inline banner 和单一重连/重试动作。
- 文本选择、复制粘贴、IME、ANSI、链接/路径识别、鼠标滚动、窗口 resize 与常用快捷键体验至少达到 macOS Terminal。
- Swift 版额外保留会话切换后的 viewport、断线恢复和历史分页，因此不能把终端实现成普通日志 TextEditor。

## 动效

- 使用系统默认 navigation、sheet、popover 动效。
- AI 执行中用细微 pulse 或 progress，不用旋转光圈和大面积渐变。
- 尊重 Reduce Motion；所有信息不能只靠动画表达。

## 无障碍与本地化

- 中文和英文都必须在 125% 字号下不截断关键操作。
- 所有 icon-only button 有 accessibility label 和 help。
- 状态同时使用图标、文字和颜色。
- 对比度达到 WCAG AA；代码 Diff 对色觉缺陷提供 `+/-` 和行背景纹理差异。
