# Agent 摘要等待与原运行恢复修复

## 故障证据

本地 Todo Executor 于 2026-11-11 18:07 启动，18:11 进入 `needs_review`，错误为 `active summary poll timed out after 120000 ms`。云端同一 Todo 的摘要任务 18:09:30 开始，18:13:51 成功结束，处理 9 条记录。摘要未失败，是客户端固定两分钟等待期限先结束了。

11 月 12 日用户多次点击继续，Swift 运行记录新增了执行入口事件，Rust Run 的版本、更新时间和失败结果却未变化：恢复入口仅查询已有 Host Run，没有发出恢复命令。

## 实现

- 共享 AI Runtime 持续等待云端摘要的实际状态，由服务端任务期限和租约回收决定结束。单次请求错误仍正常上报，调用者取消或失去租约仍中止等待。删除客户端摘要总等待期限，不通过延长期限掩盖任务状态。
- 明确的继续或重试操作恢复同一 Host Run、Turn 和 checkpoint，携带运行与会话版本进行原子状态校验。启动时对账不自动重试需要检查的运行，等待用户回答的运行也不被空回答恢复。
- 需要检查的 Host Run 映射为需要检查，不再混成普通暂停。恢复开始立即显示运行状态。
- 恢复事务同时重新打开 Turn，清理旧终止结果；再次中断或成功时更新同一可见结果，避免终止状态冲突及重复主键。Memory 中的中断诊断按 Run 版本单独保留。

## 回归验证

- 虚拟时钟下摘要持续五分钟后成功；失败、接口错误与取消均可结束等待。
- 真 SQLite 内存库完成两次中断及恢复，最终成功；保留 checkpoint，清除旧终止结果，重放恢复命令幂等，启用 Memory 投影验证诊断无冲突。
- Mac Host Stub 验证明确恢复发出恢复命令及正确版本，不创建重复 Turn；启动对账和等待用户回答不触发恢复。
- 群聊调度、取消和恢复现有测试一并回归。
