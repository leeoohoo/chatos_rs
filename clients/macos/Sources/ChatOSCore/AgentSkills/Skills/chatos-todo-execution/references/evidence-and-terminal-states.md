# Todo execution evidence and terminal states

## Progress

Good: record a completed stage after an observable milestone, including commands, files, test results, or external responses at an appropriate level of detail.

Bad: append every internal thought, repeat unchanged status, or claim progress based only on elapsed time.

## Completion

Check every expected output and acceptance criterion. Distinguish edits from verification, local verification from deployment, and proposal submission from Human approval.

Suggest a team asset update only for durable project knowledge such as architecture, conventions, decisions, or current-state references. Provide complete Markdown and a factual rationale.

## Blocking

Block when required authority, information, access, or a safe recovery path is absent. State the exact condition and the smallest action that could unblock it.

## Cancellation and resume

If the delivery or Todo is cancelled, stop side effects. On resume, read saved progress and current state before repeating an action; never assume an interrupted write did or did not happen without evidence.
