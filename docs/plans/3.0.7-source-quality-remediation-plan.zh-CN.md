# ChatOS 3.0.7 源码质量、安全与性能修复方案

> 编写日期：2026-09-24
> 目标分支：`3.0.7`
> 基线分支：`3.0.6`（基线提交 `b7adb6804`）
> 状态：待实施；由人工审阅与定时修复任务共同推进

## 1. 目标

3.0.7 聚焦本轮源码审计发现的高风险安全边界、确定性性能热点和超大源码文件。实施时遵守以下原则：

1. 安全问题优先于性能与结构整理。
2. 每次只提交一个可独立验证、可独立回滚的修复切片。
3. 先补失败测试或基准，再修改行为；不能通过降低校验、扩大权限或跳过测试来“修复”。
4. 数据库优化必须保留现有权限语义、排序稳定性、分页语义和 API 返回结构。
5. 超大文件拆分只做行为保持型重构，不与功能修改混在同一提交。
6. 生成代码、第三方源码和构建产物不手工拆分；应从生成器、依赖或打包流程治理。

## 3. Phase 1：安全边界修复

### 3.1 解除 User Service 与 Harness 的密码耦合

- [ ] 为 Harness 注册/登录流程增加请求体测试，证明当前用户密码不会出现在下游请求、日志、错误和持久化记录中。
- [ ] 确认 Harness 支持的服务端预配或凭据交换方式；优先使用内部受认证的预配接口。
- [ ] 如果 Harness 仍要求密码，改为 User Service 生成的独立高熵随机预配凭据，不得复用用户密码；凭据只服务于预配/恢复流程，并尽快换取最小权限访问令牌。
- [ ] 将现有 `encrypted_password` 字段迁移为明确命名的 Harness 专用预配密钥，或在无需重试凭据后删除该字段。
- [ ] 清理失败路径，确保调试日志、HTTP 错误、审计事件和 tracing 字段不包含敏感值。
- [ ] 为旧记录增加兼容迁移：不得在用户再次登录时读取旧的可逆用户密码继续预配。

验收：注册、登录、Harness 暂时不可用和重试四条路径都通过；数据库与捕获的 Harness HTTP 请求中均不存在用户提交的原始密码。

### 3.2 宿主机文件系统默认失败关闭

- [x] 将宿主机根目录开关改为默认 `false`，不再由 `NODE_ENV` 的缺失、拼写或自定义值隐式开启。
- [x] 仅接受显式布尔开关启用，并在启动日志中记录“已启用”事件，但不输出敏感路径内容。
- [ ] 默认根只包含按用户隔离的 workspace/public 目录。
- [ ] home、`.ssh`、仓库父目录不得被隐式加入；若确有管理用途，必须通过单独、明确、可审计的配置开放。
- [ ] 增加表驱动测试，覆盖 `NODE_ENV` 缺失、development、production、大小写、空值及两个兼容开关的组合。
- [ ] 增加符号链接、路径穿越、读写权限和根目录重叠的回归测试。

验收：无显式开关时，任意部署环境都无法访问用户隔离目录以外的宿主机路径。

## 7. 每个修复切片的强制流程

每次人工或定时任务运行只选择上面一个未完成复选框，执行：

1. `git fetch origin`，确认当前分支是 `3.0.7`，工作区没有来源不明的改动。
2. 阅读该问题的调用链、数据模型、现有测试和最近相关提交；不得仅凭本文行号直接修改。
3. 先添加能复现问题的测试、查询计划或基准；记录修复前证据。
4. 实施最小修复，保持公共 API 和持久化兼容；需要迁移时同时提供回滚/兼容路径。
5. 运行相关包的格式化、静态检查与测试。涉及 Rust 公共 crate 或数据库接口时，再运行：

   ```bash
   cargo check --workspace --all-targets
   cargo clippy --workspace --all-targets -- -D warnings
   cargo test --workspace --all-targets
   ```

6. 检查 `git diff --check`，审阅 diff 中的权限扩大、敏感信息、无界查询、锁范围和错误吞噬。
7. 更新本文复选框和证据说明，提交单一主题 commit，并推送到 `origin/3.0.7`。
8. 若测试失败、远端出现不可安全快进的提交、需要产品决策/凭据/数据库操作或发现用户未提交改动：停止，不覆盖、不 stash、不强推，并报告阻塞。

## 9. 定时任务停止条件

满足下列任一条件时，定时任务不得继续写代码，只报告状态：

- 本文所有实施项与发布门禁均完成；
- 当前 checkout 不是 `3.0.7`，或存在无法归因的未提交改动；
- `origin/3.0.7` 与本地发生分叉，无法安全快进；
- 连续测试失败且最小修复不能在本次运行内验证；
- 修复需要生产凭据、外部服务变更、破坏性数据迁移或产品决策；
- 发现修复会扩大文件系统、身份或网络权限。

任务在没有可安全执行的切片时保持安静；只有完成并推送修复、发现新风险、测试失败或需要人工决策时通知。
