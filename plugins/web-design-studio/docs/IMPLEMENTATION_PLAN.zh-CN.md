# Web Design Studio 插件实施方案

## 1. 目标

开发一个面向 ChatOS/Codex 的可视化网站设计插件，让用户能够：

- 用自然语言让 AI 创建或修改网页设计；
- 在同一个工作台中实时查看页面；
- 从组件库拖入文本、按钮、图片、卡片、输入框等组件；
- 直接拖动组件、调整尺寸并修改常用样式；
- 选中具体组件添加批注；
- 针对选中组件提交 AI 修改请求，并让 AI 只修改目标组件及必要的关联内容；
- 保存结构化设计文档；在明确需要交付代码时再导出 HTML/React/Vue。
- 管理多个网站页面、页面路径和独立组件树；
- 导入图片到文档资源库并在页面间复用；
- 直接导出当前响应式断点的独立 HTML 文件。
- 将选中的组件树保存为可复用组件，并在不同页面插入实例；
- 统一管理颜色、圆角和字体设计 Token；
- 在预览模式切换页面路由，配置组件点击交互，并导出带路由的 React/Vue 组件。

## 2. 已调研实现

### Figma 插件

Figma 插件采用“插件清单 + Skills + 远程 MCP + Connected App”的组合，适合连接既有设计平台。它证明了设计类插件需要同时提供可发现的能力描述、AI 工作流说明和可交互界面，但其编辑器本身由 Figma 承担，不适合作为本项目的直接代码底座。

### Visualize 插件

Visualize 通过 Skill 生成独立的交互式 HTML，可快速产生预览，但没有持久化设计文档、组件级编辑、批注和多人/AI 协作模型，更适合一次性可视化。

### ChatCut 插件

ChatCut 采用大量细分 Skills 配合 MCP 工具，把复杂编辑任务拆成明确工作流。这个模式适合后续将网站设计拆分成“生成页面、修改组件、响应式适配、设计审查、代码导出”等独立技能。

### Diagram Studio 插件

Diagram Studio 是最接近本项目的参考实现，已经具备：

- ChatOS 与 Codex 双清单；
- React/Vite 可视化工作台；
- 本地 HTTP 应用运行时；
- 结构化 JSON 文档与 revision 乐观锁；
- MCP 读取、局部 patch、校验和导出；
- 用户拖动、缩放、选择、属性编辑与本地持久化。

Web Design Studio 将沿用这套架构，并把“图节点”替换为“网页组件”，增加组件批注和 AI 请求队列。

## 3. 总体架构

```text
ChatOS/Codex 对话
      │
      │ MCP：创建、读取、局部修改、处理批注
      ▼
Web Design Studio MCP ──────┐
                            │ 同一份结构化文档
                            ▼
                    Document Store
                            ▲
                            │ HTTP API + revision
                            │
Web Design Studio Workbench ┘
  ├─ 组件库
  ├─ 页面画布
  ├─ 拖动/缩放/选择
  ├─ 属性检查器
  ├─ 组件批注
  └─ AI 修改请求
```

核心原则是：画布和 AI 不直接操作互不兼容的 HTML 字符串，而是共同读写有稳定组件 ID 的结构化设计文档。用户手工编辑和 AI patch 都采用 revision 乐观锁，避免覆盖对方的修改。

## 4. 数据模型

当前版本采用绝对定位画布，并用父子结构和容器布局描述组件关系。文档包含：

- 页面标题、画布宽高和背景；
- 带稳定 ID 的组件列表；
- 组件父子关系，以及 free/Flex/Grid 容器布局配置；
- 每个组件的位置、尺寸、层级、类型、文本和视觉样式；
- 绑定到组件的批注；
- 绑定到页面或组件的 AI 请求；
- revision、创建时间和更新时间。

当前版本已经支持复用组件实例同步、覆盖属性和基础点击交互。后续版本扩展数据绑定以及 React/Vue 真实项目级组件映射。

## 5. AI 交互协议

界面不直接持有模型密钥。用户可以针对整页或选中组件提交修改要求，工作台会自动保存请求。AI 通过 MCP：

1. 列出待处理请求；
2. 读取当前文档和目标组件；
3. 使用 `web_design_apply_patch` 做局部修改；
4. 使用 `web_design_resolve_request` 标记请求已完成；
5. 工作台刷新后立即呈现结果。

平台后续增加 `conversation.prompt` 或 `agent.run` Plugin UI Bridge 能力后，界面的“提交给 AI”按钮可以直接唤起一次对话执行；现有 Artifact Bridge 暂时只支持上下文和产物读写，不能安全地直接启动模型任务。

## 6. 分阶段实施

### 阶段一：可运行基础版

- 创建双清单插件骨架、Skill、MCP、本地应用运行时；
- 实现结构化设计文档、校验、revision 持久化；
- 实现页面画布、组件库、拖入、选择、拖动、右下角缩放；
- 实现位置、尺寸、文本、颜色、圆角等属性编辑；
- 实现组件批注和 AI 请求记录；
- 实现 MCP 的 list/create/get/apply-patch/list-requests/resolve-request；
- 完成构建、单元测试、MCP smoke test 和本地应用 smoke test。

## 7. 阶段一验收标准

- 插件清单通过校验并可被 ChatOS/Codex 发现；
- 本地工作台能够启动并保存设计；
- 用户可拖入、选中、移动、缩放和编辑组件；
- 用户可对选中组件添加批注和 AI 请求；
- AI 可通过 MCP 精确读取并 patch 指定组件；
- 并发修改通过 revision 冲突显式失败，不静默覆盖；
- 自动化测试覆盖数据校验、MCP 主流程和本地服务启动。
