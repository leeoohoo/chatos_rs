# macOS 客户端性能问题与修复计划

更新时间：2026-09-20

## 目标

修复 2026-09-20 对当前 `/Applications/ChatOS.app` Debug 构建进行静态审计与运行时采样时发现的资源生命周期、图片内存、会话缓存、持续动画和高频轮询问题。修复不能削弱插件隔离、聊天实时性、全局宠物、剪贴板历史或 Visual Session 能力。

## 采样基线

- 主进程 CPU 连续采样约为 9%–16%。
- 主进程 RSS 约为 898–906 MB；`vmmap` physical footprint 约为 618 MB，峰值 691 MB。
- `Image IO` 常驻约 402 MB，在数分钟观察窗口内保持稳定。
- 系统中存在 42 个由 ChatOS 插件目录启动、父进程已经变为 PID 1 的 Node 进程；RSS 合计约 2.73 GiB，最长存活超过 15 天。
- Visual Session 每 450 ms 无条件检查一次；剪贴板历史前台每 300 ms、后台每 600 ms 检查一次。

以上主进程数据来自 Debug 构建，只用于定位和前后对比；最终资源预算必须用 Release 构建复测。

## 修复清单

### P0：插件应用进程泄漏

- [x] Plugin Application 与 MCP Plugin 一样使用独立进程组启动。
- [x] 停止时先向整个进程组发送 `SIGTERM`，超时后发送 `SIGKILL`，并回收直接子进程。
- [x] 应用正常退出时同步触发本机运行时清理，不能依赖无法保证完成的临时异步任务。
- [x] 启动时清理由本应用记录、但已经失去宿主的历史插件进程组。
- [x] 增加包含孙进程的退出测试，断言停止后进程组不再存在。

验收：重复打开插件应用并退出 ChatOS 20 次后，系统中不得残留对应 Plugin Application 进程。

### P1：图片预览内存过量

- [x] 文件读取层除压缩字节限制外，再限制图片像素数量。
- [x] 二进制图片在内存中保持 `Data`，不再以 Base64 `String` 跨层传递。
- [x] SwiftUI `body` 不直接执行 Base64 和 `NSImage` 解码。
- [x] 使用 ImageIO 按目标显示尺寸生成缩略图，并关闭立即缓存完整原图。
- [x] 图片缓存设置条目数和总成本上限，关闭标签页后可释放。

验收：预览一张大像素图片时，单张预览的新增 physical footprint 不超过约 80 MB；关闭标签页后可被系统回收。

### P1：会话缓存与 Realtime 生命周期

- [x] `ConversationSessionViewModel` 提供幂等 `activate` / `deactivate`。
- [x] 切换资源时停止旧会话的 Realtime、重试和预加载任务。
- [x] 会话缓存改为有限 LRU；当前会话和正在发送的会话不得被错误淘汰。
- [x] 登出和应用退出时停止全部缓存会话。
- [x] 增加切换多会话后的活动订阅数与 LRU 淘汰测试。

验收：连续访问 30 个会话后，缓存和 Realtime 订阅数均保持在配置上限内。

### P2：桌面宠物持续渲染

- [x] 动画仅在宠物可见、应用未被系统休眠且未开启 Reduce Motion 时运行。
- [x] 空闲动画降低刷新频率；不可见时展示静态帧。
- [x] 精灵图按实际显示尺寸解码，避免完整大图长期驻留和重复 ImageIO 缓存。
- [x] 应用激活状态、可见状态变化能立即暂停或恢复动画。

验收：宠物隐藏时不再出现 `TimelineView` 周期渲染；宠物可见且空闲时 Release CPU 应接近空闲预算。

### P2：常驻轮询与系统唤醒

- [x] Visual Session 没有活动 descriptor 或没有可展示会话时采用退避，不按 450 ms 永久轮询。
- [x] Visual Session 仅在活动画面存在时使用快速刷新。
- [x] 剪贴板轮询根据应用活跃状态和连续无变化次数退避，检测到变化后恢复低延迟。
- [x] 系统休眠和功能关闭时取消对应任务，唤醒或重新启用时恢复。
- [x] 为轮询间隔策略增加确定性单元测试。

验收：完全空闲时不再产生 300–600 ms 级永久轮询；Visual Session 活跃时仍能在 1 秒内反映画面变化。

## 修复后复测（2026-09-20）

复测对象为仓库内新打包且签名的 Debug App：
`clients/macos/.build/ChatOS.app`。没有覆盖 `/Applications/ChatOS.app`。

| 指标 | 修复前 Debug 构建 | 修复后 Debug 构建 |
| --- | ---: | ---: |
| 空闲/宠物可见 CPU | 约 9%–16% | 12 次采样平均约 1.4%，峰值 4.0% |
| RSS | 约 898–906 MB | 约 193 MB |
| physical footprint | 约 618 MB，峰值 691 MB | 约 72.1 MB，峰值 78.4 MB |
| ImageIO | 约 402 MB | `vmmap -summary` 未报告独立 Image IO 常驻区 |
| 线程 | 15 | 9–10 |
| 打开项（`lsof`） | 214 | 157 |
| 已建立网络连接 | 未单独记录 | 采样时 0 |
| PPID 1 的历史插件应用进程 | 42 个，RSS 合计约 2.73 GiB | 新构建启动清理后 0 个 |

CPU 复测先在宠物可见时完成，随后切换到其他应用并抓取 5 秒调用栈；后台样本中未再出现 `PetSpriteAnimationView` 或 `TimelineView`。共享账户当时仍有本地 Agent 任务继续执行，因此任务启动后的 CPU 不计入空闲指标。

验证结果：

- 完整 `swift test` 通过；仓库中两个需要显式环境变量启用的数据量/UI 基准测试按设计跳过。
- `./scripts/package-debug-app.sh` 构建、资源校验和临时签名全部通过。
- Plugin Application 测试会启动孙进程，并验证 `stopAll()` 后整个进程组被清理。
- 图片测试覆盖二进制 `Data` 传递和 64 MP 像素预算；预览器固定生成最长边 2048 的缩略图，缓存限制为 8 项/64 MiB。
- 会话测试覆盖 Realtime 取消；30 个不同会话的 LRU 策略测试验证最终只保留最近 8 个。
- Visual Session 和剪贴板间隔策略均有确定性测试；系统睡眠时任务取消，唤醒时按启用状态恢复。
