# ChatOS Local Browser Control

This Bundle uses the ChatOS-owned Local Connector BrowserTools bridge. It does not contain or redistribute Codex's proprietary in-app browser implementation.

- The desktop installer includes pinned `agent-browser 0.31.2` and Chrome for Testing runtimes. Users do not need to install npm, run `npx`, or execute `agent-browser install`.
- The dependency check fails closed when the packaged runtime is incomplete. `AGENT_BROWSER_BIN` and `AGENT_BROWSER_EXECUTABLE_PATH` remain development overrides only.
- Use `browser_tabs` to list open pages before multi-tab work. `browser_tab_new`, `browser_tab_switch`, and `browser_tab_close` use stable session-scoped IDs such as `t1`; IDs are never array indexes, and the last remaining page tab cannot be closed.
- Tab results contain at most 64 page tabs. Titles are bounded, URL-shaped titles follow the URL sanitizer, web URL credentials are removed, query values are replaced with `[REDACTED]`, and data/file/javascript/internal URLs are omitted.
- Use the published browser tools for navigation, inspection, clicking, typing, scrolling, console/network observation, research, bounded workspace file transfer, sanitized HAR capture, bounded read-only WebSocket frame observation, stable multi-tab control, and explicitly approved session-scoped route interception. Refresh page snapshots after navigation, switching tabs, or large DOM changes.
- `browser_route_add` requires mandatory local user approval for the exact normalized pattern, action, and mock JSON body. It accepts only bounded ASCII HTTP(S) URL globs without credentials, query, fragment, whitespace, backslashes, or advanced glob syntax. Rules can only abort requests or return one fixed JSON body up to 16 KiB; they cannot inject headers, credentials, scripts, arbitrary status codes, or arbitrary CDP commands.
- A managed browser session can hold at most 32 ChatOS-owned routes. Every route expires after 30 minutes. Expiry removes the exact route; if safe removal fails, the runtime closes that managed browser session so an expired interception cannot remain active. Duplicate patterns are rejected.
- `browser_route_list` returns pattern/action/timestamps and mock body size plus SHA-256, never the mock body. `browser_route_remove` accepts only an opaque session-owned `route_id`; `browser_route_clear` is an unprivileged recovery operation that removes all ChatOS-owned rules.
- The Local Connector settings page provides a separate high-risk “完整 CDP 存取权限” developer switch. It is disabled by default and requires explicit risk acknowledgement when first enabled. When disabled, `browser_cdp_command` is not published in the prepared tool snapshot.
- When the full CDP switch is enabled, every exact `browser_cdp_command` method, target, params object, and timeout still requires mandatory local user approval. The command connects only to the validated loopback browser endpoint for the current managed session, caps params at 64 KiB, timeout at 15 seconds, and result output at 4 MiB. The debugger URL is never returned to the model or renderer.
- Full CDP responses may contain cookies, storage, page content, browser diagnostics, or other sensitive internals. Use `browser_cdp_command` only when the normal bounded Browser tools cannot perform the task, request the narrowest command possible, and do not assume approval for one command applies to another.
- The ChatOS managed-session panel uses a bearer-authenticated Local Connector API to consume a continuous CDP `Page.startScreencast` stream. One validated loopback CDP connection is bound to the canonical workspace and UI conversation identity; the renderer receives only bounded JPEG data URLs and never receives the debugger URL, port, target ID, attached CDP session ID, or WebSocket transport.
- Screencast frames use JPEG quality 70 with 1920 x 1080 requested bounds. Each decoded frame is limited to 5 MiB, each edge to 4096 pixels, and total pixels to 16 Mi; malformed base64, incomplete JPEGs, invalid metadata, mismatched attached sessions, and oversized CDP messages are rejected. Every accepted or rejected frame with a valid frame ID is acknowledged immediately so Chrome cannot block waiting for an ACK.
- The runtime keeps only the newest frame, assigns a monotonically increasing session sequence, and supports bounded long-poll reads that omit duplicate frame bytes. A stream is stopped when the panel closes, the active tab changes, the managed browser closes, or the 30 minute lifetime expires. At most 64 process-wide streams may be active.
- The existing bounded `Page.printToPDF` preview remains a compatibility fallback only when continuous screencast setup or delivery fails. It captures at most two pages around the current scroll position, limits CDP messages to 12 MiB and decoded PDFs to 8 MiB, is never persisted, and reports an explicit fallback warning.
- `browser_network` reads the real captured CDP request log with bounded URL/method/status/resource-type filters. Query values, credentials, Cookie/Authorization, and unknown header values are always redacted; request/response bodies are omitted from list results.
- `browser_network_request` reads one validated request ID. Text request/response bodies are returned only with explicit include flags, capped at 64 KiB each, and redacted for sensitive JSON/form/common credential fields. Binary or base64 bodies remain unavailable.
- `browser_har_start` starts a session-scoped HAR capture. Use it only immediately before the flow that needs cross-request diagnosis, and stop it promptly.
- `browser_har_stop` writes one new workspace-relative `.har` file without overwriting. The raw HAR exists only in a private temporary directory and is deleted before publication. Exported query and cookie values, credential-like and unknown header values are always redacted. Bodies are omitted by default; explicitly requested text bodies are capped at 64 KiB each and redacted, while binary/base64 bodies remain unavailable. Exports contain at most 1,000 recent entries and at most 64 MiB.
- `browser_websocket_start` starts a read-only observer for the current attached managed page. It connects only through the validated loopback browser CDP endpoint, enables only the Network domain needed for WebSocket events, expires after 30 minutes, tracks at most 256 sockets, stores at most 1,000 recent frames and 1 MiB of sanitized text, and exposes no WebSocket input primitive.
- `browser_websocket_frames` returns at most 200 recent frames and can filter by validated request ID or `sent`/`received` direction. Text payloads are omitted by default. Explicit text reads return at most 4,096 characters per frame after sensitive JSON/form fields, credential assignments, bearer values, URL query values, and likely long tokens are redacted. Binary payloads are never returned.
- `browser_websocket_stop` promptly stops and removes the session observer. Start observation immediately before the flow under diagnosis and stop it as soon as the required frames have been read.
- `browser_upload` accepts 1-10 existing workspace-relative regular files. It rejects symlinks, files over 50 MiB, totals over 100 MiB, traversal, absolute paths, and paths outside the selected workspace.
- `browser_download` clicks a fresh element ref and writes at most 100 MiB to a new workspace-relative file. The parent directory must already exist. Existing paths are never overwritten; staging and failed outputs are removed.
- Browser commands execute from the authorized workspace and use a run-scoped conversation/session identity. WebSocket observers, screencasts, and interception records are additionally bound to the canonical workspace and conversation identity.
- The ChatOS managed-session panel exposes the same tab, network, HAR, WebSocket, file-transfer, and preview contracts. The full CDP switch lives only in authenticated Local Connector settings and does not expose a raw debugger transport to the panel.
- Do not claim browser vision or full CDP access is available unless the prepared tool list explicitly includes the corresponding tool.
