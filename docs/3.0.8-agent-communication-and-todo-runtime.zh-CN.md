# Agent 沟通层与 Todo 执行层

## 最终模型

ChatOS 本地 Agent 只有两种运行身份，群聊、私聊和项目都不是运行身份。

### Agent 沟通层

一条发给 Agent 的消息只负责唤醒目标 Agent。正常启动、主动巡检和失败重试走同一条流程：

1. 恢复该 Agent 稳定的 manager Memory thread；
2. 注入 ChatOS 即时通讯渐进披露 Skill；
3. Agent 调用 `chat_read_all_unread` 读取全部群聊和私聊未读；
4. Agent 读取任务板和调度状态；
5. Agent 使用统一的 `chat_send_message` 回复或主动联系其他 Agent；
6. 处理完成后调用 `agent_cycle_complete`。

唤醒消息所属 room 只作为内部 durable delivery 的来源和重试凭据，不进入 Agent 的运行范围，不决定 Memory，不决定工具集合，也不向新 Run 注入“当前群角色”“当前群目标”或 trigger 正文。

`chat_send_message` 不接收 `conversation_ref`：

- 回复未读：传 `reply_to_message_ref`，通讯层从消息引用解析会话；
- 主动联系 Agent：传 `target_agent_ref`，通讯层自动创建或复用私聊并唤醒目标 Agent；
- 主动发团队消息：传 `team_ref`；
- 回复本次唤醒消息：可以省略目标。

历史 `chat_inbox_send`、`chat_team_send`、`chat_direct_open` 和 `chat_direct_send` 已从工具注册、执行实现、提示词和 Skill 指引中删除，不提供执行兼容。尚未完成的旧 Run 若继续调用这些工具会失败；客户端随后依据持久化的未读消息和 Todo 事实，使用新架构重新唤醒 Agent，而不是续跑旧工具调用。

### Todo 执行层

Todo 被调度时启动独立执行 Run。它只绑定当前 Todo：

- 使用 `client-agent:todo:<todo-id>` 独立 Memory thread；
- 只获得 Todo 目标、范围、验收条件、已完成前置结果和进度；
- 只获得该 Todo 明确授予的内建能力和 Plugin；
- 不继承 Agent 沟通层 Memory；
- 不读取全部未读，不负责群聊或私聊发送；
- 通过 `todo_complete` 或 `todo_block` 结束。

Todo 状态变化会再次唤醒对应 Agent 的沟通层，由沟通层读取任务事实并决定协调、重试、拆单、升级或对外汇报。

## 不变量

- Agent manager Memory 按 Agent 稳定，跨群、跨项目、跨私聊和跨唤醒复用。
- Todo Memory 按 Todo 稳定，只在该 Todo 的重试之间复用。
- 发送目标错误返回可恢复的结构化 MCP 结果，不得令整个 Agent Run 进入 `needsReview`。
- 新 Run 只暴露账户级未读、统一发送、任务与必要附件工具；当前会话专用入口不再暴露。
- room/project 标识可以留在内部 delivery、审计和存储记录中，但不能成为模型的运行作用域。
