# ChatOS Local Browser Control

This Bundle uses the ChatOS-owned Local Connector BrowserTools bridge. It does not contain or redistribute Codex's proprietary in-app browser implementation.

- The desktop installer includes pinned `agent-browser 0.31.2` and Chrome for Testing runtimes. Users do not need to install npm, run `npx`, or execute `agent-browser install`.
- The dependency check fails closed when the packaged runtime is incomplete. `AGENT_BROWSER_BIN` and `AGENT_BROWSER_EXECUTABLE_PATH` remain development overrides only.
- Use `browser_tabs` to list open pages before multi-tab work. `browser_tab_new`, `browser_tab_switch`, and `browser_tab_close` use stable session-scoped IDs such as `t1`; IDs are never array indexes, and the last remaining page tab cannot be closed.
- Tab results contain at most 64 page tabs. Titles are bounded, URL-shaped titles follow the URL sanitizer, web URL credentials are removed, query values are replaced with `[REDACTED]`, and data/file/javascript/internal URLs are omitted.
- Use the published browser tools for navigation, inspection, clicking, typing, scrolling, console/network observation, research, bounded workspace file transfer, sanitized HAR capture, bounded read-only WebSocket frame observation, and stable multi-tab control. Refresh page snapshots after navigation, switching tabs, or large DOM changes.
- The ChatOS managed-session panel requests a bounded visual preview through the bearer-authenticated Local Connector API and exposes a native tab strip for listing, creating, switching, and closing tabs. The renderer never receives a CDP URL, stream port, or direct browser WebSocket capability.
- Preview capture accepts only a validated loopback browser CDP endpoint, a single attached non-internal page target, a viewport up to 4096 x 4096 and 16 Mi pixels, at most two print pages around the current scroll position, a 12 MiB CDP message, and an 8 MiB decoded PDF. The frontend rasterizes the transient PDF locally and crops it to the current scroll offset.
- The PDF preview path is a compatibility containment for Chrome runtimes where `Page.captureScreenshot` or the agent-browser screencast can stall. It is read-only, uses `Page.printToPDF`, does not persist the PDF, and never grants arbitrary CDP commands or WebSocket input to the renderer.
- `browser_network` reads the real captured CDP request log with bounded URL/method/status/resource-type filters. Query values, credentials, Cookie/Authorization, and unknown header values are always redacted; request/response bodies are omitted from list results.
- `browser_network_request` reads one validated request ID. Text request/response bodies are returned only with explicit include flags, capped at 64 KiB each, and redacted for sensitive JSON/form/common credential fields. Binary or base64 bodies remain unavailable.
- `browser_har_start` starts a session-scoped HAR capture. Use it only immediately before the flow that needs cross-request diagnosis, and stop it promptly.
- `browser_har_stop` writes one new workspace-relative `.har` file without overwriting. The raw HAR exists only in a private temporary directory and is deleted before publication. Exported query and cookie values, credential-like and unknown header values are always redacted. Bodies are omitted by default; explicitly requested text bodies are capped at 64 KiB each and redacted, while binary/base64 bodies remain unavailable. Exports contain at most 1,000 recent entries and at most 64 MiB.
- `browser_websocket_start` starts a read-only observer for the current attached managed page. It connects only through the validated loopback browser CDP endpoint, enables only the Network domain needed for WebSocket events, expires after 30 minutes, tracks at most 256 sockets, stores at most 1,000 recent frames and 1 MiB of sanitized text, and exposes no CDP command or WebSocket input primitive.
- `browser_websocket_frames` returns at most 200 recent frames and can filter by validated request ID or `sent`/`received` direction. Text payloads are omitted by default. Explicit text reads return at most 4,096 characters per frame after sensitive JSON/form fields, credential assignments, bearer values, URL query values, and likely long tokens are redacted. Binary payloads are never returned.
- `browser_websocket_stop` promptly stops and removes the session observer. Start observation immediately before the flow under diagnosis and stop it as soon as the required frames have been read.
- `browser_upload` accepts 1-10 existing workspace-relative regular files. It rejects symlinks, files over 50 MiB, totals over 100 MiB, traversal, absolute paths, and paths outside the selected workspace.
- `browser_download` clicks a fresh element ref and writes at most 100 MiB to a new workspace-relative file. The parent directory must already exist. Existing paths are never overwritten; staging and failed outputs are removed.
- Browser commands execute from the authorized workspace and use a run-scoped conversation/session identity. WebSocket observers are additionally bound to the canonical workspace and conversation identity so Browser panel start/read/stop requests cannot cross sessions.
- The ChatOS managed-session panel exposes the same tab, network, HAR, WebSocket, file-transfer, and preview contracts; its WebSocket area provides explicit Start, Refresh, Clear, Stop, direction filtering, and opt-in redacted text reads without granting arbitrary host filesystem access or exposing raw browser credentials.
- Do not claim browser vision is available unless the prepared tool list explicitly includes it.
