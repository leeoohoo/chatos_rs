# Web Design Studio 3.0.1：阶段 D Camera 工作区进度

## 已完成：Camera 基础与独立持久化

- 删除固定 `4800 × 3600` DOM 滚动层，不保留旧 Infinite Canvas 兼容路径。
- 新增统一 `WorkspaceCamera` 数学模型：World/Screen 坐标转换、任意方向平移、指针锚定缩放、适应画板和显示区域求解。
- 缩放范围固定为 `10%–800%`；平移不再受 `scrollLeft >= 0` 或有限世界边界限制。
- 中心工作区改为 `translate3d + scale` Camera 投影，页面内部组件坐标不会因平移或缩放而改变。
- 网格随 Camera 平移和缩放，画板仍在独立 World 坐标中渲染。
- 鼠标滚轮平移；Ctrl/Command + 滚轮围绕指针位置缩放；空格拖动、中键拖动和 Hand 工具共用同一 Camera。
- 去掉底部工具栏上方持续遮挡内容的操作说明，只保留明确的按钮名称、快捷键和 tooltip。
- 工具栏补齐“适应选择”“适应画板”“显示全部”“100%”四个明确 Camera 动作；适应选择支持单选和多选组件，使用画板 World 坐标合并范围、留白并居中。
- “适应画板”按当前画板的实际内容高度求解，不再只是贴合视口宽度；“显示全部”同样纳入每个画板真实增长后的内容边界。

## Workspace Placement Store

- 新增 `WorkspacePlacementStore`，Camera 与后续 Artboard Placement 独立于网站设计文档保存。
- 存储按 runtime scope fingerprint 与 documentId 物理隔离；宿主 projectId 继续只参与 Scope 注入，不由网页或模型传入。
- 新增 Studio API：
  - `GET /api/workspace/:documentId`
  - `PUT /api/workspace/:documentId/camera`
  - `PUT /api/workspace/:documentId/artboards`
- 本地预览 Repository 使用相同的 Workspace Placement 结构；服务模式写入插件数据目录。
- Camera 保存不会修改网站设计 revision，也不会改变用户页面布局。

## 已完成：页面与界面状态流程画板

- 新工作区首次打开时为文档中的每个逻辑页面创建一个画板，不再默认创建桌面、平板和手机三个设备投影。
- 工作区存储升级为 schema v2；每个画板独立保存 `artboardId / pageId / surfaceKind / viewportWidth / viewportHeight / x / y`，画板位置和检查视口变化不进入设计文档。
- `surfaceKind` 区分页面、弹窗、抽屉、浮层、菜单和界面状态；默认工作区不再为同一页面创建桌面、平板、手机三份投影视图。
- 画板是长期设计对象。AI 单次只处理一个可验证步骤，可以在同一画板上多轮继续，也可以在安全提交点暂停后再恢复。
- 非活动画板有明确的“选择此画板”覆盖层；点击画板或顶部标题后，页面和属性面板同步切换到该设计面。
- 顶部标题可直接拖动画板，拖动使用 Workspace World 坐标，不改变页面内部节点坐标。
- 顶部工具栏新增页面、弹窗、抽屉、浮层、菜单和界面状态类型选择；每次创建的是独立可设计画板，并自动放在现有画板右侧。
- 页面切换只激活对应画板，不再改写其他画板的 `pageId`。
- 响应式预设、旋转和自定义宽高只检查当前画板，不创建额外画板。
- 页面高度由当前画板实际可见内容边界决定，内容向下增长时画板外框同步增长。
- 设计面类型同时写入设计文档的 Page 元数据；普通页面参与路由，弹窗、抽屉、浮层和菜单作为独立目标画板。
- 组件在原型面板连接到非页面设计面后，全屏预览会把目标画板叠加回来源页面；Drawer 靠右展开，其余叠层按对应容器预览。
- 工作区加载时会剔除没有对应设计面的孤立画板，并为尚未摆放的页面补齐画板，避免设计文档和 Placement 异步保存造成幽灵状态。

## 已完成：工作区原型关系可视化

- 工作区会从组件的页面连接关系生成独立流程边，不把连线写回用户布局，也不改变组件坐标。
- 连线从来源组件右侧连接到目标画板左侧，使用 World 坐标计算；移动画板、调整组件或缩放和平移 Camera 后都会保持正确指向。
- 页面、弹窗、抽屉、浮层、菜单和界面状态共用同一套流程边模型；缺失目标和同画板自连接不会渲染误导性的箭头。
- 流程线使用紫色贝塞尔曲线和方向箭头，位于画板内容之下，不拦截画布选择、拖动或第三方组件交互。
- 顶部工作区显示关系数量，并允许临时隐藏或重新显示连线，便于在复杂页面中专注视觉编辑。
- 原型属性面板新增结构化关系卡，明确展示“来源 → 行为 → 目标”，可一键定位目标画板或移除关系。

## 已完成：可见区域运行时虚拟化

- Camera 使用屏幕视口、平移和缩放计算每个画板是否进入可见区域，不依赖有限世界边界。
- 离开可见区域的第三方 UI 库运行时会卸载为轻量占位，避免大量页面同时挂载 iframe、React/Vue 组件及动画。
- 画板距离视口 `480px` 时提前恢复真实运行时，平移到目标画板时不会等到完全进入屏幕后才加载。
- 普通设计元素、画板标题、尺寸和原型连线保持渲染，因此虚拟化不会改变布局、选择关系或流程结构。

## 已完成：大量画板分段渲染

- 画板按与视口的屏幕距离统一划分为 `anchor / shell / content / runtime` 四个渲染层级，不为每个组件库编写单独分支。
- `runtime` 层挂载完整普通节点和第三方运行时；`content` 层挂载普通节点并把第三方组件降为轻量占位；`shell` 层只保留标题、背景和选择壳层；`anchor` 层只保留绝对定位锚点。
- 层级预加载边距依次为 `480px / 720px / 1200px`，平移接近目标时逐步恢复内容，避免等到画板进入屏幕后才突然挂载完整 DOM。
- 当前活动画板始终保持完整运行时，避免用户在平移离开后丢失选择、输入或组件内部状态。
- 分段渲染只影响 React DOM 和第三方运行时挂载，不改变 Artboard Placement、页面节点、原型连线或保存数据。

## 已完成：Slot/聚焦编辑统一 Camera

- 删除内部内容编辑独立的 `slotEditorZoom` 与 CSS `zoom` 路径，不保留双坐标系兼容逻辑。
- Form、Card、Drawer、Modal 等内容区域进入聚焦编辑后继续使用中心工作区的 `WorkspaceCamera`；滚轮平移、指针锚定缩放、空格拖动、中键拖动和 Hand 工具行为与外层画板一致。
- 首次进入内容区域时按真实 Slot 画布宽高和标题框完整适配；内容增长后不强制重置用户已经调整的视角。
- 内部工具栏提供“适应选择”“适应内容”“100%”，多选组件范围会转换为 Slot 局部 World 坐标后统一求解。
- 组件拖动、缩放、左侧拖入和官方预览元素精确放置都使用 Camera zoom 反算，不再分别维护内部缩放比例。
- 进入聚焦编辑时保存外层工作区 Camera；返回页面后恢复原平移与缩放，内部临时视角不会写入 Workspace Placement Store。
- 聚焦编辑期间继续保留外层 Artboard Placement 内存状态，返回页面不再触发无意义的工作区卸载和重读。
