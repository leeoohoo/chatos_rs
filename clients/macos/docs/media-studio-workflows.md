# AI 创作工作流（macOS）

## 目标

把现有独立的图片、视频创作入口合并为可保存、可重复运行的线性工作流。用户先在工作流列表中新建或选择一个工作流，再进入流程图编辑器配置节点。

首期仅支持从左到右的线性流程。节点不分支、不合流、不循环；视频节点只能出现一次且必须是最后一个节点。

## 页面结构

AI 创作顶部保留三个入口：

1. 工作流：工作流列表与流程图编辑器。
2. 剧情模式：保持现有实现。
3. 记录：保持现有图片、视频和剧情历史。

工作流列表展示名称、节点摘要和更新时间，支持新建、打开和删除。进入工作流后，画布从左到右展示：

```text
流程输入 → 文本节点 → 图片节点 → 文本节点 → 视频节点
```

选择节点后，在右侧配置模型、节点提示词、节点参考图和类型专属参数。

## 数据模型

工作流包含：

- 稳定 UUID、名称、创建时间和更新时间；
- 可编辑的流程输入提示词与流程参考图；
- 1–8 个模型节点；
- 节点按数组顺序执行。

模型节点包含：

- 稳定 UUID；
- `text`、`image` 或 `video` 类型；
- 模型配置 ID；
- 节点提示词；
- 节点参考图；
- 图片尺寸，或视频尺寸、比例和时长。

工作流只保存模型配置 ID，不保存 API Key。参考图片复制到当前账号的工作流资产目录，清单只保存相对路径、MIME、文件大小和稳定 ID。

## 节点输入和输出

运行时维护当前文本和当前图片：

```text
currentText
currentImages
```

流程输入初始化这两个值。每个节点另外拥有自己的参考图。

### 文本节点

- 输入：节点提示词、当前文本、当前图片、节点参考图；
- 输出：纯文本；
- 输出替换 `currentText`，图片继续传递；
- 有图片输入时，所选文本模型必须声明 `supports_images=true`。

### 图片节点

- 输入：节点提示词、当前文本、当前图片、节点参考图；
- 输出：一张图片；
- 当前图片排在节点参考图之前，合计最多 8 张；
- 生成图片成功保存到本机后，替换 `currentImages`；
- 首期每个图片节点固定生成一张，避免隐式分支。

### 视频节点

- 输入：节点提示词、当前文本和一张首帧图片；
- 每个视频节点最多上传一张节点参考图；
- 节点参考图存在时优先作为首帧，否则使用 `currentImages` 的最新图片；
- 输出视频并结束工作流，后面不能再添加节点；
- 必须复用现有持久视频任务、恢复和提交不确定态保护，不能直接绕过任务存储调用服务商。

## 提示词组合

首期不增加模板语言。程序按固定格式组合节点提示词和当前文本：

```text
节点要求：
<node prompt>

当前工作文本：
<current text>
```

用户不需要学习 `{{input}}` 等额外语法。图片通过模型附件或媒体请求字段发送，不转写进提示词。

## 持久化与账号隔离

工作流数据存放在 Application Support 下独立于现有媒体历史的目录：

```text
ChatOSSwift/MediaStudio/Workflows/Accounts/<owner-hash>/<workflow-id>/
  workflow.json
  assets/
```

要求：

- 所有目录和清单按认证账号隔离；
- 本机来源图片在授权期间完成验证和复制；
- 清单拒绝绝对路径、路径穿越、符号链接、超限文件和未知 MIME；
- 删除节点时删除其不再引用的资产；删除工作流时删除对应目录；
- 退出登录或切换账号时取消运行、清空内存状态并拒绝迟到结果；
- 现有图片、视频 `record.json` 不迁移、不改写。

## 执行与失败处理

运行前冻结一份工作流和输入快照，运行期间禁止编辑参与本次运行的配置。

- 节点严格串行执行；
- 节点开始、完成或失败都会更新画布状态；
- 任一节点失败，后续节点不执行；
- 已成功生成的图片和视频仍保留在现有创作记录；
- 图片生成成功但本机保存失败时停止流程，避免把不稳定的远程结果传给下游；
- 首期失败后可重新运行整个工作流，不保存或恢复断点；
- App 重启后不恢复文本和图片中间态；持久视频任务仍按现有机制恢复，避免重复计费。

## 实施顺序

1. 增加工作流领域模型、校验和账号隔离存储。
2. 增加普通文本节点服务，复用 Responses 客户端及本地图片附件。
3. 增加顺序执行器，复用图片用例和持久视频任务。
4. 把图片、视频 Tab 替换为工作流列表与流程图编辑器。
5. 增加节点级图片导入、删除和类型专属设置。
6. 完成领域、存储、执行器、ViewModel 和关键交互回归。

## 验收标准

- 可以创建多个命名工作流，重启后仍能打开；
- 可以新增、删除和调整文本、图片、视频节点顺序；
- 视频节点后不能添加节点，非法清单也会被拒绝；
- 每个模型节点都能保存自己的参考图；
- 文本 → 图片 → 文本 → 视频能按顺序传递文本和图片；
- 节点失败后不会调用后续模型；
- 账号切换不会看到或写入其他账号的工作流与资产；
- 现有创作记录、剧情模式和视频任务恢复行为不回归。

## 首期明确不做

- 分支、合流、循环和条件节点；
- 自由端口连线和任意 DAG；
- 多人协作、云同步和工作流市场；
- 变量表达式或提示词模板语言；
- 跨重启恢复文本、图片中间节点。
- 从失败节点断点续跑（视频任务仍保留现有持久恢复能力）。
