# Writing, content, and marketing scenarios

Decompose around audience, channel, evidence, and editorial ownership. Expected outputs should specify deliverable, audience, language, tone, length, channel, call to action, source requirements, and variants. Acceptance criteria should cover grounding, hierarchy, terminology, voice, grammar, sections, and format.

If the user's limit applies to the entire final textual response, also bind `final_response_max_chars`. This counts Unicode scalar values including whitespace, punctuation and Markdown. A requested word count, body-only limit or exported-file limit is not this field: specify its counting convention in acceptance and require actual measurement. For example, a 400-character full-response limit must include the title and closing explanation, not merely the main draft. Delivery length and editorial quality are separate checks; satisfying one does not establish the other.

Useful graphs include research/fact checking + message strategy -> draft -> edit; shared campaign brief -> parallel channel variants -> consistency review; glossary -> parallel localization -> native QA; and documentation inventory -> parallel topic files -> link/API review.

Use prerequisites when a draft needs approved facts, positioning, glossary, or outline. Channel variants can run in parallel after a shared brief. Do not make every paragraph a Task. For regulated or technical claims, separate evidence collection from persuasive writing and require citations or a source ledger.
