# Progress examples

Good updates:

- “Confirmed the timeout comes from an idle-read deadline that is reset only after complete events; updating it on every stream frame.”
- “Implemented the shared binding catalog; static tool coverage and runtime registration tests now pass.”
- “Deployment is blocked because the selected environment rejected authentication; a new credential or environment choice is required.”

Bad updates:

- “Called search.” “Read file.” “Ran test.” — too granular and repetitive.
- A raw terminal transcript, stack trace, source file, token, or password.
- “Done” without naming the result or evidence.
- Hidden deliberation, speculative conclusions, or promises about work that has not happened.

For a long phase, update when its state materially changes, not on a fixed timer. If repeated operations produce no new conclusion, do not emit another record merely to show activity.
