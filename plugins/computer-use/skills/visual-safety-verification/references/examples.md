# Safety examples

## Positive: publish

Verify the account, destination, exact content, and publish button; obtain required confirmation; click once; then verify the published state or authoritative status.

## Negative: inferred authorization

Treat “open the draft” as permission to publish it, or treat “check permissions” as permission to change system settings.

If the click result is obscured or the app is still loading, report the last visible confirmed state rather than claiming success.
