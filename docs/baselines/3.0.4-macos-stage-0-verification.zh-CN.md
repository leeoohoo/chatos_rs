## 3. 本次重跑结果

### 3.1 行为 characterization

以下筛选门禁通过，共 53 个测试、0 失败：

- Core：`AgentGroupChatCodableContractTests` 5 个；
- Connector：历史迁移 1 个、Tool Provider 5 个、Scheduler 12 个、Store 30 个。

执行命令：

```bash
swift test --package-path clients/macos \
  --filter '(AgentGroupChatHistoricalMigrationTests|SQLiteAgentGroupChatStoreTests|LocalAgentChatToolProviderTests|LocalAgentGroupChatSchedulerTests|AgentGroupChatCodableContractTests)'
```

### 3.2 两组 opt-in 固定规模基线

两组基线同时通过：

```bash
CHATOS_RUN_AGENT_STORE_BASELINE=1 \
CHATOS_RUN_AGENT_UI_BASELINE=1 \
swift test --package-path clients/macos \
  --filter '(AgentGroupChatStorePerformanceBaselineTests|AgentGroupChatViewModelPerformanceBaselineTests)'
```

稳定计数继续保持：

- 最近 20 条消息：42 条 SQL；
- 500 条消息工作区快照：1008 条 SQL；
- 空闲 heartbeat 500 次检查：500 条 SQL、0 写入；
- 空闲账号 drain：103 条 SQL、0 写入；
- ViewModel 首次激活：349 条 SQL、45 次 UI 发布；
- 500 change burst：合并为两次完整刷新，合计 246 条 SQL、42 次 UI 发布。

耗时受当前机器负载影响，本轮 Store 快照和空闲 drain 出现明显冷/热差异，因此只把 SQL、写入与发布计数作为重构硬快照；耗时只用于后续同环境三轮前后比较。

## 4. 已确认并排入阶段 4 的问题

1. 消息读取存在 N+1：最近 20 条消息需要 42 条 SQL，500 条消息工作区快照需要 1008 条 SQL。
2. 空闲账号级 drain 每轮执行 103 条 SQL，虽然不产生写入。
3. 500 个无持久化变化事件虽被有界 stream 合并成两次刷新，仍执行 246 条 SQL 并触发 42 次 UI 发布。

这些问题已有可重复前测，但阶段 1–3 不改变行为；只有阶段 4 才允许在同一 fixture 上做前后对比修复。

## 5. 非阻塞专项门禁

以下不足不阻塞阶段 1 的 Core/Store 纯拆分，但必须在对应组件开始拆分前补齐：

1. 阶段 2 Tool Provider：现有测试冻结工具集合和关键 schema，但尚无 37 个工具逐字节 JSON Schema/响应 golden；拆分 registry/response DTO 前先增加稳定 canonical golden。
2. 阶段 3 UI：现有性能测试冻结激活和重复事件合并，但 `AgentGroupChatViewModel` 的选择保持、旧消息分页、错误恢复与 generation 取消仍缺直接 characterization；UI 拆分前补齐。
3. MainActor 探针只能发现调度间隔，不能替代 Instruments；阶段 4 声称主线程性能改善前必须补 signpost 或真机采样。
