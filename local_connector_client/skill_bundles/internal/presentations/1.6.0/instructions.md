# ChatOS Presentations

Use this Skill to inspect, create, conservatively append, exactly reorder, safely delete, or precisely replace visible and speaker-note text in editable PPTX presentations inside the authorized local workspace.

- Use `inspect_pptx` before and after an edit. It validates package paths, the presentation slide list, internal slide relationships, complete slide-part reachability, and expanded size. It reports the exact widescreen dimensions, slide files in true visible presentation order, per-slide title/text previews, internal image relationships, media-file count, and speaker-note previews.
- Use `create_pptx` for a new 1–200 slide widescreen deck. Use `append_pptx_slides` to append slides to an existing deck. Use `reorder_pptx_slides` to apply one exact full permutation of current one-based slide positions. Use `delete_pptx_slides` to remove selected current one-based positions while keeping at least one slide. Use `replace_pptx_text` for exact visible-text replacement and `replace_pptx_notes_text` for exact speaker-note replacement in selected positions. Every editing tool writes a distinct output file; the source deck is never modified.
- `replace_pptx_notes_text` resolves `slide_numbers` against the current true visible presentation order, then edits only each selected slide's uniquely owned standard notesSlide part. It never creates notes, changes visible slide XML, rewrites relationships, or guesses ownership. Missing notes simply cannot match.
- Speaker-note replacement validates note ownership across the complete visible deck before writing output. Multiple or external notesSlide relationships, shared notes parts, missing notes parts or relationship parts, multiple or external owning-slide back-references, and owner mismatches fail closed.
- `delete_pptx_slides` resolves `slide_numbers` against the current visible presentation order, not slide filenames. It removes each selected slide part, its relationship part when present, its presentation relationship, and its content-type override. A uniquely owned standard speaker-note part, its relationship part, and its content-type override are removed with the owning slide.
- Slide deletion rejects empty selections, duplicates, out-of-range positions, deleting every slide, custom shows, presentation sections, extra slide relationships, shared speaker-note parts, mismatched notes-to-slide ownership, missing content types, and complex/non-empty relationship or content-type entries. It does not guess-delete media, chart, embedded-object, theme, master, or layout parts because those package parts may be shared.
- `reorder_pptx_slides` requires `slide_order` to contain every current slide position exactly once. It rejects missing, duplicate, out-of-range, unchanged, or partial orders. It changes only `ppt/presentation.xml`; existing slide IDs, relationship IDs, slide parts, slide relationships, notes, media, masters, themes, and unrelated package entries remain unchanged.
- Reordering and deletion accept only one standard presentation slide list whose slide IDs are unique empty elements without extension or mixed content. Every package slide part must be referenced exactly once through an internal presentation relationship. Missing, duplicate, external, escaping, orphaned, complex slide-list, or mixed-namespace metadata fails before output is persisted.
- `replace_pptx_text` only matches inside one standard `a:t` DrawingML text run and never guesses across multiple runs, shapes, slides, notes, fields, or XML extension content. `replace_pptx_notes_text` applies the same exact single-run rule inside notesSlide XML and never guesses across runs, shapes, slides, or notes pages. Both preserve surrounding run properties and all unrelated package parts. Use `slide_numbers` to narrow the search and `max_replacements` to bound changes; results report matched visible slide positions, the exact replacement count, and whether the limit was reached.
- Supported creation and append layouts are `title_body`, `title_only`, `section`, `two_column`, `image_right`, and `image_full`. Appended slides inherit the last existing slide's slide-layout relationship while unchanged ZIP entries, including the original slides, masters, themes, media, and metadata, are copied without reserialization.
- `title_body` is the default compatibility layout. `section` creates a centered section divider. `two_column` uses `left_body` and `right_body`. `image_right` and `image_full` require an `image` object and reject missing images rather than silently changing layout.
- Lines beginning with `- ` or `* ` become editable DrawingML bullet paragraphs. Other lines remain ordinary editable text paragraphs.
- Images must be workspace-local PNG or JPEG files, at most 10 MiB each, at most 20000 pixels per edge and 40 megapixels. Combined image input is limited to 50 MiB. `contain` preserves the full image inside its box; `cover` uses bounded centered DrawingML cropping. Alt text is required and is written to the picture description. Source image files are read-only and never modified.
- Optional `notes` become standard editable notesMaster/notesSlide speaker notes. New decks create a standard notesMaster when needed. Appending speaker notes requires exactly one existing internal notes master; a deck without one fails closed instead of receiving a guessed or replacement master. Reordering and exact visible-text replacement do not modify speaker-note content; exact notes replacement modifies only selected uniquely owned notesSlide text runs; deletion removes only a deleted slide's uniquely owned notes part.
- Deck text is limited to 500000 characters per create/append operation, 100000 characters and 2000 lines per slide field. Exact visible or speaker-note replacement find text is limited to 10000 characters, replacement text to 100000 characters, and replacement count to 10000. XML-incompatible control characters fail before any output is persisted. The resulting deck remains limited to 200 slides for editing, reordering, and deletion.
- PPTX output uses a same-directory temporary file, defaults to refusing existing targets, rejects in-place edits and symlink/non-file sources or targets, duplicate/unsafe ZIP entries, more than 10000 entries, and compressed or expanded output above 100 MiB. Edited XML parts are limited to 16 MiB.
- This bounded native adapter does not replace text across multiple DrawingML runs, import arbitrary themes or masters, create tables/charts/SmartArt, change animation/transition metadata, render PDF/PNG previews, or perform visual QA. It does not launch PowerPoint, Keynote, LibreOffice, or a cloud presentation service.
