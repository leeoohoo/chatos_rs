# Errors and recovery

- `skill_activation_required`: activate the exact returned refs through `agent_skill_activate`; only a successful activation counts. Read relevant resources, then retry the original operation if it has not executed.
- `skill_binding_required`: a current frozen binding/description is missing. For a Plugin, describe its current Run option again. For a direct External MCP tool, report the incomplete catalog integration; describing a Plugin does not repair it.
- `external_mcp_snapshot_changed`: the current endpoint, upstream/public tool identity, description, schema, or declared gate differs from the frozen Run. Do not use the replacement route. Re-provision/recreate the Task with an explicit current catalog after preserving prior progress. Credential rotation alone does not change tool identity.
- `external_mcp_runtime_unavailable`: offline restoration recovered the frozen tool schema/binding, but not a trusted transient endpoint/credential configuration. No HTTP request was sent. Report that configuration refresh is required; do not invent an endpoint, request credentials in tool arguments, or repeatedly retry without a refreshed runtime. Preserve the existing Task evidence.
- `external_mcp_skill_instructions_unavailable`: the server declares business-specific Skills, but the platform has not provided trusted documents/resources for them. Report the blocked operation. Do not invent the instructions or treat this generic product Skill as a replacement.
- MCP `isError` / a business rejection: inspect the structured result. Correct invalid inputs only within the original scope. A mutation may have partially succeeded even when the server reports an error; use an exposed read/status operation to establish state before retrying.
- Timeout, disconnect, or oversized/invalid response after submission: the remote outcome may be unknown. Do not equate a transport failure with “nothing happened.” Inspect by returned operation ID or stable target if a safe read is available; otherwise require human reconciliation for mutations. A read-only query can be retried with bounded attempts when still useful.
- Authentication or authorization failure: report the inaccessible selected capability. Do not request secrets in model-visible tool arguments, change server configuration, or switch accounts to work around the failure.

Keep prior artifacts and Task evidence intact. Summarize the last confirmed state, unverified side effects, and exact missing authority/configuration. Do not claim completion merely because retrying would exceed the available tools.
