# Todo 执行线程的精简汇报

1. Todo 的过程事实继续写入 `todo_progress_append`，不要把完整过程复制到聊天消息。
2. 最终汇报先给结论，再给最强的一条验证证据、剩余风险和下一步；普通研发任务尽量控制在 150～400 个中文字符。
3. 不要在聊天正文重复任务说明、验收标准、完整文件清单、命令日志或大表格；用户需要采取行动时，单独用一句话明确写出要确认什么。
4. 详细交付、长日志、代码或大表格需要展开时，在本轮提供 `chat_document_create` 的前提下创建 Markdown 文档并随最终消息附加。
5. 不得用多条连续消息规避正文限制，也不得用一次性附件替代团队长期共享资产。
6. 如果当前 Run 没有文档创建工具，不得声称已创建附件；保留精简结论并通过 Todo 进度保存必要执行现场。
