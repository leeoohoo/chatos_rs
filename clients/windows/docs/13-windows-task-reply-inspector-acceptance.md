## 正常显示与错误

1. 在联系人和项目聊天各找到一条任务回执。点击“执行过程”，核对当前任务标题、状态和过程；点击“任务详情”，核对任务描述及最新运行报告。同一按钮再次点击应折叠；折叠清理详情、错误和加载状态。
2. 在可控测试服务上分别制造任务读取失败、运行详情读取失败。当前请求失败应显示错误并结束加载；折叠后重新打开可以重试，成功后清除错误。取消或离开会话不应显示“读取失败”。
3. 核对无任务上下文的普通回复不会发起回执详情读取。不同回执仍可各自展开，本轮没有改为 Mac 的全时间线单面板选择策略。

## 慢速与过期请求

4. 让首次“执行过程”读取缓慢，依次切换“任务详情”→“执行过程”。先返回旧成功或旧错误，再返回最新结果；随后反过来先返回最新结果。两种顺序下，旧请求都不得改变当前任务/报告、错误、栏目或加载状态。
5. 在读取期间再次点击当前按钮折叠，再返回旧成功/错误。面板不能重新打开，不能保留旧错误或加载环；重新展开使用新请求。服务若忽略取消，客户端仍应丢弃旧结果。
6. 分别在任务读取前、等待任务期间及等待运行详情期间取消。取消后不得继续发起后续运行详情请求；已发出的请求即使晚到成功，也不能更新面板。
7. 读取期间切换联系人/项目会话、离开会话，或刷新目标轮次使其 Revision 增加。旧面板应关闭并取消读取，晚到结果不能写入旧条目或新会话；关闭客户端也应取消。另一会话即使有相同轮次 ID，也不能复用旧面板。内容变化的目标轮次仍重新创建，本次没有保留其中未变化的单条回复或自动重载详情。
8. 对未变化轮次，分别在详情已加载、过程已展开、读取中、读取失败时刷新历史。面板和错误应保留，进行中的请求不应被取消，当前请求随后成功/失败仍更新同一面板。再依次触发其他轮次的实时追加、加载较旧历史、其他轮次更新及发送失败后的乐观消息移除，核对原面板和轮次过程仍展开。记录实际滚动与焦点；集合不再 Reset 的自动化断言不能代替这两项 UI 验收。
9. 在中英文、深浅主题、窄窗口和字体缩放下复测按钮、加载环、错误及报告，核对键盘/焦点、读屏和滚动。记录入口、构建、请求完成顺序、实际截图及通过/失败/未执行；不得使用账号绕过入口或从源码、日志搜集凭据。
