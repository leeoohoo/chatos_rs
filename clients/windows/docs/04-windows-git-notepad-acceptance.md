# Windows Git 与记事本验收

## 构建

在 Windows 11、Visual Studio 2022 Build Tools 和 .NET 8 SDK 环境执行：

```powershell
dotnet restore ChatOS.Windows.sln
dotnet build ChatOS.Windows.sln -c Debug -p:Platform=x64
dotnet test ChatOS.Windows.sln -c Debug -p:Platform=x64 --no-build
```

ARM64 设备或交叉打包时把 `x64` 改为 `ARM64`。macOS 只能完成 Core/API/Presentation/Connector 编译；WinUI XAML 编译器会调用 Windows `kernel32.dll`，因此 Desktop 的最终编译必须在 Windows 执行。

## Git

1. 安装 Git for Windows，确认 PowerShell 中 `git --version` 可用。
2. 打开一个绑定到当前 Windows Connector 工作区的项目，进入项目顶部 `Git`。
3. 对非仓库目录执行初始化，确认只新增 `.git`，项目文件不改变。
4. 新建、修改、删除和重命名文件，确认工作区状态、暂存状态和两类 Diff 分开显示。
5. 暂存并提交；未配置 `user.name`/`user.email` 时应显示可操作错误，配置后提交成功并进入历史。
6. 创建、切换和合并分支。制造会被覆盖的未提交修改后切换分支，应被 Git 拒绝且文件内容保持不变。
7. 添加、编辑、重命名和删除远端。拉取只允许 fast-forward；无 upstream 的首次推送自动为当前分支设置 upstream。
8. 在拉取或推送期间点击取消，确认 UI 恢复、Git 子进程停止、可再次刷新。
9. 使用包含空格和中文的仓库路径、文件名与分支名复测；再在未安装 Git 的机器确认安装提示。

## 记事本

1. 点击主窗口标题栏的记事本按钮，确认直接进入记事本而不是空白占位。
2. 新建多级目录和笔记，搜索标题、标签或正文；选择和刷新后当前笔记保持稳定。
3. 修改正文后直接切换另一篇笔记，确认旧笔记先保存；保存失败时不得切换并丢失输入。
4. 默认打开为预览；编辑和分栏模式可输入，标题、列表、引用和代码块有基本 Markdown 语义。
5. 重命名或递归删除目录前显示明确确认；删除当前笔记或其所在目录后编辑区清空，删除其他笔记或目录不得清空当前编辑区。
6. 导出为 `.md`，用记事本或 VS Code 打开确认 UTF-8 中文和换行正确。
7. 关闭记事本后回到此前工作区，项目/联系人选择不变化。
8. 保存包含中文、空行和尾部空格的正文，确认保存后正文、光标和滚动位置稳定；响应只有元数据时也不得清空正文。关闭重开后核对已持久化内容。
9. 在保存响应较慢时继续修改标题、标签或正文，确认本次只提交点击时的快照，后续输入保留且继续显示未保存；再次保存后状态清除。保存期间显示进度，保存、刷新、搜索和关闭不可用，点击其他笔记不得重复提交。
10. 修改笔记后点击另一篇触发自动保存；若保存期间又输入，确认停留原笔记且列表选择与编辑区一致。保存失败也须保留原笔记和全部输入，显示错误并可重试；无新输入且保存成功时正常切换。
11. 编辑当前笔记后，搜索一个只匹配其他目录笔记或没有命中的关键词。确认原笔记的标题、标签和正文不变，未保存状态保留，结果可跨目录显示；清空关键词后再次搜索，恢复当前目录列表。保存当前未命中笔记不应将它插回筛选结果。
12. 在慢搜索期间执行另一关键词搜索，确认仅最新请求更新结果；旧请求的结果或失败不得覆盖新结果或结束新进度。当前搜索失败时保留已有结果和输入，并可再次搜索重试。
13. 慢搜索期间继续编辑并点击关闭，确认搜索被取消，仍可在关闭确认中保存或取消；取消关闭后输入保留。筛选刷新无命中不得清空编辑区；完整刷新发现当前笔记缺失时仍须保留未保存内容。
14. 修改标题、标签和正文后关闭，分别验证“保存”“放弃”“取消”：保存成功再关闭，放弃后重开恢复最近成功读取或保存的版本且不写入未保存内容，取消则保留输入；先成功保存一次再修改、或保存失败后选择放弃，也应恢复正确基线。保存尚在进行时不得执行放弃。
15. 当前笔记有未保存修改时新建，确认先保存原笔记再打开新笔记；原笔记保存失败时停留原文，不得创建。保存等待期间继续输入标题、标签或正文，确认保留新输入并停止新建，保存后可再次操作；新建目标目录取提交创建请求时的目录，不随保存期间的目录导航改变。
16. 创建请求较慢时继续修改原笔记，确认响应不会覆盖这些输入，显示已创建并保留新修改的提示；保存原笔记后可从创建目录打开新笔记。新笔记打开后目录读取仍在等待时继续输入，确认读取完成或失败都不改变正文。请求期间新建入口不可用，连续触发不得重复创建。
17. 模拟创建成功、随后目录列表读取失败，确认新笔记和创建成功提示保留，错误明确区分目录刷新失败并提示无需重复新建；恢复连接后点击刷新，确认目录恢复且不新增重复笔记。创建接口本身失败时保留原编辑区并允许重试。
18. 搜索结果中创建一篇不匹配关键词的笔记，确认现有结果和关键词保持，编辑区可打开新笔记；若等待创建时又编辑原文，则保留原文。清空关键词后执行搜索，可在目标目录找到新笔记。慢创建或目录读取期间关闭并重开，旧响应或旧错误不得替换新会话的编辑、提示和进度；已送出的创建可能已在服务端完成，应刷新确认，不能把关闭视为删除新笔记。
19. 点击另一篇笔记后，在详情读取较慢时继续修改当前笔记的标题、标签或正文。响应到达后应留在原笔记、保留新输入及未保存状态，并提示保存后再打开；列表高亮应恢复到实际编辑的笔记。保存后再次选择目标笔记应正常打开；没有继续输入时正常切换，读取失败时保留原文且可重试。
20. 在打开/刷新初始化、目录与列表读取、详情读取或目录变更请求较慢时关闭并重开记事本，再发起新读取。确认旧成功、失败和结束回调均不能改写新内容、错误、资源或提前停止新进度；关闭立即结束旧加载但保留草稿。取消不会弹出未处理异常；当前读取失败仍显示错误并允许重试。首次打开详情失败后应保留列表，可再次点击笔记打开。
21. 有笔记时依次切换“编辑”“预览”“分栏”：三个模式的标题和标签输入框都应位于正文上方且可编辑，切换不重建或清空输入；分栏应左侧正文、右侧预览，单栏填满正文宽度。模式单选组始终只有当前项选中，鼠标及 Tab/方向键均能操作，读屏可读出模式和输入名称。
22. 切换中英文、长标题以及不同窗口宽度/字体缩放，核对标题和标签不会被零宽列隐藏，复制/导出/保存/删除文案完整、正文和预览对齐、焦点顺序合理；默认预览和无笔记空状态仍正常。记录实际窗口尺寸、缩放、截图和未通过项目，不能以构建或匿名登录页 smoke 代替记事本布局验收。
23. 当前笔记有未保存内容时删除另一个目录，分别在删除响应和后续目录刷新等待期间修改标题、标签、正文。确认原选择、已有草稿和新输入保留，未保存状态仍正确，且不自动保存；删除 `work` 应删除其子目录，不能误删 `workshop`。若当前浏览目录被删除，回到根目录但仍保留不属于该目录的编辑笔记。
24. 删除当前笔记或其所在目录：确认后请求等待期间三个编辑字段应只读，仍可选择并复制文字；删除失败时恢复编辑，保留原文并可重试。成功后立即清空对应编辑区、从列表移除目标，再刷新目录；目录刷新失败必须明确显示删除已经完成、可刷新而无需重复删除。刷新恢复后核对服务端笔记确已删除，没有重复删除请求。搜索中删除命中目标后保持关键词和其余结果，不得用全量列表填回。
25. 删除或删除后的目录刷新较慢时关闭/取消并重开，确认旧成功、错误和结束回调不改变新会话的笔记、目录、错误或进度；取消后不能留在只读状态。已送出的删除可能仍在服务端完成，需刷新确认真实结果。补验中英文提示、键盘/读屏、删除确认期间目标、重复点击和真实后端恢复；无登录条件时明确记录未执行。
26. 打开 `work/child` 内的笔记并保留未保存内容，将 `work` 重命名为 `archive`。确认当前目录和笔记路径变为 `archive/child`，笔记 ID、文件标识、标题/标签/正文、未保存状态和光标不变。重命名等待及后续列表刷新期间继续输入，确认新输入保留；保存后重开核对真实持久化。当前编辑或浏览 `workshop` 等无关目录时，应停留该目录；等待期间主动切换的目录仅在属于重命名范围时映射到新路径。新目标包含多级父目录时，刷新失败前也应可在本地目录列表看到新路径。
27. 搜索命中 `work` 后重命名该目录，确认按已执行的关键词刷新，搜索框里尚未提交的新文字不应被执行；当前笔记即使不再命中也保留在编辑区及未保存状态。分别模拟重命名接口失败、接口成功但目录/笔记列表刷新失败：前者保留旧路径且可重试，后者保留新路径并明确提示已完成、刷新即可无需重复重命名。根目录、空目标、自身子目录不发出重命名请求；相同路径不重复操作。慢请求期间关闭重开，旧结果不得覆盖新会话。补验弹窗焦点、目录高亮、键盘、中英文错误和跨入口修改后的版本冲突。
