# Windows 插件与全局宠物验收

本清单只在 Windows 11 x64/ARM64 真机执行。macOS 可以验证 Core/API/Presentation/Connector 和 XAML XML，但不能运行 Windows XAML Compiler、Win32 layered window、Credential Manager 或多显示器 DPI 行为。

## 准备

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./build/test.ps1
./scripts/start-client.ps1
```

确认所有测试通过，并且客户端使用测试账号成功登录。

## 插件设置

1. 打开“设置 → 插件”，确认 Catalog 中只出现服务端当前发布的插件。
2. 安装三个正式插件，确认版本、发布者、权限和组件信息正确；重启后安装状态保持。
3. 禁用正在运行的插件，确认活动调用被终止；重新启用后可再次调用。
4. 输入 Secret 并保存，关闭再打开设置：只显示“已配置”，不得回显明文。
5. 发起 OAuth，分别验证成功、用户取消和 refresh token 失效；取消不得错误显示为 needs-auth。
6. 更新插件 Release，确认旧 Release 的 Secret/OAuth/session 被清理；卸载后本地目录和凭据均消失。
7. 在 Windows Credential Manager 中确认存在受控凭据条目，但 UI、日志和 ViewModel JSON 中没有 Secret 明文。

## Visual Session 画中画

1. 插件开始视觉会话后，画中画在主窗口之外置顶出现，但不把 ChatOS 主窗口拉到前台。
2. 同一 conversation 存在多个 adapter session 时可切换；只有当前选择的会话读取和刷新帧数据。
3. 快速切换会话或帧序号倒序到达时，旧帧不能覆盖当前会话的新帧。
4. PNG 与 JPEG 均可正确显示；损坏帧显示可操作错误，应用不退出。
5. 点击关闭只忽略当前视觉会话，不取消完整插件运行；其他会话仍可继续显示。
6. 插件结束会话后窗口自动隐藏；同 adapter 后续新 session 可再次出现。

## Artifact 打开与另存

1. 主窗口 Toolbar 的“插件产物”可查看所有当前产物；画中画入口只展示当前 adapter session 产物。
2. “打开”先复制到 `%LOCALAPPDATA%\\ChatOS\\ArtifactCache`，再交给默认应用；UI 和日志不出现插件原始绝对路径。
3. 非法 Windows 文件名被清洗，两个同名但不同 artifact id 不会覆盖同一缓存文件。
4. “另存为”取消后不报错且不开始复制。
5. 另存覆盖使用同目录临时文件完成后原子替换；复制失败时保留原目标并删除 `.chatos.tmp`。
6. Artifact 注册后被篡改、删除或超过限制时，打开/另存失败且不会留下半文件。

## 审批设置

1. 设置页显示当前默认模式、待处理审批和最近 30 条审计记录。
2. 切换“需要确认”立即生效；切换“自动审批”或“完全控制”必须先展示风险确认。
3. 取消风险确认后选择器恢复权威模式，不留下未保存草稿。
4. 设置页处理审批后，主窗口浮层和宠物审批卡同步消失，审计记录显示 reviewer、结果和原因。
5. AI reviewer Ready 时，分别验证结构化 `approve`、`deny`、`ask_user` 和 `remember_allow`；AI、Policy 和 Session 结论在宠物中展示约 5 秒后消失。
6. 模型、API Key 或插件 Prompt 不可用时明确安全回退用户，不得把用户决策标记为 AI reviewer。
7. 模型请求不得包含 API Key、Secret 或绝对工作区路径；UI 和日志不得包含 API Key、插件原始路径或供应商错误正文。

## 模型设置

1. “同步模型”只展示 ChatOS 当前启用且有有效 model name 的模型。
2. 选择审批模型并保存，重启 Windows 客户端后选择保持；清除选择并保存后恢复未选择状态。
3. 模型请求重试次数只能保存 0–10；手动输入超界值时按边界归一化。
4. 服务端禁用或删除已选择模型后重新同步，客户端明确提示模型不可用，不静默改用另一个模型。
5. 模型设置和错误信息不包含 API Key、Secret 或供应商认证 header。

## 全局宠物窗口

1. 登录后宠物独立显示；最小化和隐藏主窗口，宠物仍在；退出登录或关闭总开关后宠物隐藏并停止消息流。
2. 在 100%、125%、150%、200% DPI 显示器间拖动，宠物应贴合鼠标，无重影，消息框与宠物同步移动。
3. 向左/向右拖动时朝向和脚步动画一致；拖动超过阈值不得触发点击。
4. 展开消息、审批和快捷聊天时，调整窗口高度不应改变宠物的屏幕锚点。
5. 重启客户端后恢复上次位置；拔掉外接显示器后位置自动夹回可见工作区。

## 本机终端资源

1. Connector 配对两个以上工作区后，从侧栏“新建本机终端”选择不同工作区，确认分别创建平级终端资源且标题使用工作区别名。
2. 在每个终端输入命令，确认真实 ConPTY 输入、输出、当前目录和中文/IME 行为正确；界面输出达到 200,000 字符后保持有界。
3. 分别测试停止当前命令和关闭终端；子进程、孙进程和后台管道都应被完整回收。
4. 退出登录后所有本机终端进程树均退出；重新登录不恢复已关闭的活进程。
5. Connector 状态刷新短暂失败时，已经打开的终端资源不能从侧栏消失。

## 运行时语言切换

1. 在主窗口、设置、项目文件、Git、Plan、Run、远端、记事本、审批浮层、宠物审批、Ask User 和快捷聊天之间切换中英文，确认无需重启即时生效。
2. 特别检查 DataTemplate 内的文件/Git 操作按钮、运行实例、附件和列表空状态，不能残留上一种语言。
3. 已打开的本机终端和 Connector 资源标题、联系人状态与操作反馈应同步切换；用户输入、任务名、项目名和服务端内容不得被误翻译。

## 任务消息与原地处理

1. 触发执行中任务，确认显示真实任务名和“执行中”，点击取消后服务端确认状态再更新。
2. 触发完成任务，确认不会立即消失；点击摘要直接打开详情，可标记“已处理”。
3. 触发阻塞/失败，确认详情和原因可见；选择“忽略”后重连、刷新和重启均不得复活同一 stable identity。
4. 创建新 Run 使用同一 task id，确认旧 Run 的忽略不会压制新 Run。
5. 触发无需用户审批/AI 审批事件，确认按服务端 TTL 短暂展示后消失，不出现只有高度变化却没有文字的空框。

## 审批与 Ask User

1. 触发本机命令审批，确认命令、cwd、来源、风险和排队数完整展示。
2. 分别测试拒绝、本次允许、本会话允许；同会话 allowlist 不得放行参数不同的危险命令。
3. 触发 Ask User 的文本、多行、密文、单选和多选字段；全部在宠物窗口输入并提交。
4. 密文字段不应出现在日志、剪贴板或序列化状态中；取消后事件应正确结束。

## 快捷聊天

1. 点击宠物，一级列表第一项始终为“叽咕狸”。
2. 在项目“运行”页开启/关闭“设为常用项目”，宠物列表即时更新，项目与叽咕狸平级。
3. 选择已有会话，确认展示最近消息、Realtime 回复和执行中状态；可直接发送和取消。
4. 选择尚无会话的常用项目，确认自动准备项目会话，完成后无需跳回主窗口即可发送。
5. 快捷聊天打开期间触发任务通知，通知红点应出现；切回任务消息后原通知状态保持，不自动已读或忽略。
