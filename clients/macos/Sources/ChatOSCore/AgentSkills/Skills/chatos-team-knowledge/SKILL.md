# Team knowledge assets

Use assets for durable facts that future team members and Runs need. Use chat for transient coordination, Todo progress for execution evidence, and the dashboard for current structured project status.

List before reading or changing an asset. Preserve its current revision and category. Create only when no suitable asset exists; update the existing asset when the subject is the same; archive only when it is obsolete and no longer the authoritative reference.

Write self-contained Markdown with source context and avoid secrets, model-only references, temporary IDs, or unsupported claims.

Read [references/asset-lifecycle.md](references/asset-lifecycle.md) for classification, revision conflicts, duplicate prevention, archiving, and examples.
