# Design and creative scenarios

Split by independently reviewable outcomes such as research, information architecture, interaction flows, visual direction, asset production, prototype implementation, and accessibility review. Keep one small asset together when it represents one coherent decision.

Expected outputs may include moodboards, flows, wireframes, component specs, tokens, editable sources, exports, prototypes, and rationale. Acceptance criteria should name dimensions, platforms, states, content coverage, brand constraints, accessibility targets, and editable/delivery formats.

Useful graphs include constraints -> parallel visual directions -> selected-system refinement; information architecture -> parallel interaction and visual work -> integrated review; and asset inventory -> parallel asset families -> packaging QA.

Do not let parallel Tasks mutate the same design source. Give one Task source ownership and let reviewers return structured findings. Conformance and accessibility can be verified objectively; final aesthetic preference may remain a user decision.
